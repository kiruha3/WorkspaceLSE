# Комплект выдачи материалов

Серверный модуль `issuance` хранит комплект, его редакции, проверки и отдельный факт полной выдачи материала. Команды подключены к Vue-журналу `/issue-packages` и карточке экспертизы; учебные положительный и отрицательный пути проверены встроенным браузером. Завершение экспертизы не означает выдачу.

## Подготовка

Один комплект относится к материалу и всем зарегистрированным по нему работам. Нельзя подготовить полный пакет, имея права только на один из чужих номеров: чтение и каждое действие проверяются по всем работам. Черновик допускает неполные сведения, сохраняет историю и не присваивает дату выдачи.

Дополнительные документы имеют назначение и явную связь с работой: подписка эксперта, сопроводительное, уведомление, счёт либо иное приложение. Один исходный файл может быть указан для нескольких работ без копирования. Для обычного заключения категории 1/5 требуют уведомления, 2/3 — счёта, плюс подписка и сопроводительное. Материалы описываются отдельно. Итоговый файл берётся из подтверждённого окончания работы с принятой версией, а не выбирается произвольно в комплекте.

Уточнение владельца28.10.2026: категория4 с обычным заключением требует подписку и сопроводительное; категория6 — их же и принятый акт экспертного исследования вместо заключения. Для любой платной работы дополнительно нужен счёт. Прежний счёт2/3 и уведомление1/5 сохраняются; у платной1/5 нужны и уведомление, и счёт. Счёт не подтверждает оплату, предварительная оплата не добавлена как условие выдачи.

Платность указывается отдельно для каждой работы в редакции комплекта: `is_paid:true`, `false` либо `null`. Неизвестное не считается бесплатным и выдаёт blocker `billing_unknown` до уточнения; неполный черновик можно сохранить. Сумма в журнале и категория не используются вместо этого факта. Платность хранится как сведения комплекта выдачи, не как бухгалтерский регистр или банковская операция.

Для полного СНДЗ, возврата без исполнения и комплекта подписок комиссии владелец уже подтвердил состав: [решения 28.10.2026](owner-issuance-decisions-2026-10-28.md). Их реализация ещё не завершена, поэтому текущая диагностика может блокировать эти варианты; обычный шаблон не подставляется молча. Неполная отчётная статистика сама по себе не добавлена как запрет выдачи.

Бумажный оригинал приложения может учитываться без скана. Загружаемой копии для готовности нужен сохранённый файл. В черновике отсутствие файла допустимо и видно как недостача. При потере доступа к приложению его реквизиты скрываются; редактирование всей редакции требует доступа к прежним приложениям, чтобы пустой проекцией не удалить скрытое содержимое.

## API

Префикс `/api/v1`. POST требует непустые `reason` и `Idempotency-Key`; сохранение редакции также требует `expected_version`. Ответ `{event:{id},package:PackageDTO}`. Создание — 201, редакция — 200. Повтор ключа возвращает прежнее событие и актуальную карточку; другой ввод с тем же ключом или устаревшая версия — 409. Нынешние права проверяются и при повторе.

| Путь | Назначение |
| --- | --- |
| GET `/materials/{id}/issue-packages/` | Материал, существующий комплект либо null, право подготовки |
| POST `/materials/{id}/issue-packages/` | Создать единственный черновик комплекта |
| GET `/issue-packages/` | Журнал по разрешённой области, поиск и фильтры |
| GET `/issue-packages/{id}/` | Текущая редакция, история, все работы и диагностика |
| POST `/issue-packages/{id}/draft/` | Полная новая редакция описания и приложений |
| GET `/issue-packages/{id}/readiness/` | Недостающие сведения и состояние готовности |
| GET `/issue-packages/options/` | Назначения документов и способы выдачи |
| GET `/issue-packages/{id}/document-options/?kind=invoice&search=…` | Доступные совместимые документы для выбора |
| POST `/issue-packages/{id}/check/` | Зафиксировать проверенный состав окончаний и версий файлов |
| POST `/issue-packages/{id}/issue/` | Отдельно записать состоявшуюся передачу материалов |
| GET `/expertises/{id}/issue-status/` | Краткий факт выдачи своей работы без чужого состава |

Содержание: `materials_description`, `note`, `items:[{kind,expertise_id,document_id,note}]`. Принятые виды `kind`: `expert_subscription`, `cover_letter`, `notification`, `invoice`, `other`. Итоговый документ не принимается как произвольный дополнительный «результат». Повтор назначения для одной работы запрещён, кроме дополнительных `other`.

Необязательный `billing:[{expertise_id,is_paid}]` обновляет платность перечисленных работ. Пропущенные работы, отсутствующий список и `[]` сохраняют значения предыдущей редакции; явный `is_paid:null` очищает значение до неизвестного. Дубликаты, неизвестная работа/работа другого материала и лишние поля отклоняются400 без частичных записей. У новой работы без явной записи значение неизвестно. В DTO `content.billing`/`content_history[].billing` содержат сохранённые факты, `works[].is_paid` — значение текущей редакции. Новых маршрутов и прав нет, применяется существующее `issue.prepare` по всем работам материала.

Способы выдачи — расширяемый справочник `issue-methods`. Команда `seed_issue_catalogs` добавляет исходные способы только при отсутствии кода, не восстанавливает отключённые значения и не сбрасывает названия. Реальным ролям новые права автоматически не добавляются.

## Проверка и фактическая выдача

Проверка требует `expected_version` и `reason`. Она сохраняет текущую редакцию комплекта, включая платность работ, подтверждённое окончание каждой работы, принятый итоговый файл и версии дополнительных документов. Новая работа, корректировка окончания, новая редакция комплекта (включая изменение платности) либо новый файл приложения делают проверку устаревшей. Поздняя версия итогового документа не меняет уже принятую версию окончания.

Команда выдачи требует `expected_version`, `reason`, `issued_on`, `method_id`, `recipient_name`, `recipient_basis`; необязательны `tracking`, `comment`, `evidence_document_id`. Дата должна быть не раньше поступлений и окончаний, не в будущем. Подтверждение может быть бумажным оригиналом; у загружаемой копии нужен файл. Его версия сохраняется отдельно. Выдача не отправляет письмо, не закрывает контроль и не предполагает оплату счёта.

Под блокировкой материала повторно проверяются все работы, состав и актуальность проверки. Одновременная регистрация нового номера или корректировка результата не могут пройти вместе с выдачей противоречивого пакета. После выдачи обычное изменение поступления, новый номер и корректировка закрытого результата отклоняются до отдельной процедуры. Старые успешные команды допускают повтор по прежнему ключу при сохранённых нынешних правах, не создавая второй факт.

Полная карточка требует области всех работ. Отдельный файл может читаться по одной разрешённой связи с работой вместе с правами `expertise.view`, `issue.view`, `documents.view`, без раскрытия чужих работ или разрешения загружать новую версию. Краткий статус выдачи различает `unavailable`, `not_issued`, `issued`; ограниченная ссылка на весь комплект не открывает его состав.

Для существующих учебных ролей предусмотрен явный `infra/local.py workflow-demo --enable-issuance`: добавляет только новые права `issue.view/prepare/check`, не восстанавливает отозванное старое `issue.confirm` и другие права; отказывается расширять роль с неучебным участником. Для реальных сотрудников права назначаются через редактор ролей. Vue включается по `supported_modules:issuance` и назначенным правам.

## Оставшаяся работа

Одно независимое ревью выявило два существенных замечания; их регрессии и исправления прошли точечные и общие проверки: 302 серверных и 150 клиентских тестов, TypeScript и сборка. Неутверждённые комплекты, повторная/частичная выдача, исправление после выдачи, автоматическая печать и реквизиты счёта остаются явными следующими задачами общей цели.

Общий файловый helper теперь перед первым POST `/documents/` сохраняет стабильный `Idempotency-Key` для нормализованных метаданных. Повтор после потери ответа возвращает тот же ID и актуальные версии, не создавая второй документ или аудит; изменение метаданных начинает новую попытку. Сервер повторно проверяет права загрузки и чтения. Заголовок поддержан без поломки прежних вызывающих без ключа; для таких устаревших вызовов гарантия повтора не добавляется. Загрузка файла и факт выдачи имеют собственные ключи.

Основной просмотр приложений выданного комплекта, как и история, использует `files` именно проверки `issuance.check_id`, связь — `item_id`. Принятый `accepted_version_id:null` бумажного документа не заменяется поздним сканом. Другую версию можно открыть явно с предупреждением, но она не становится частью выдачи. При отсутствии снимка не подставляется текущий latest.
