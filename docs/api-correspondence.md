# Переписка и контроль ответов

Модуль `backend/apps/correspondence` хранит самостоятельные входящие и исходящие письма, связи с материалом и несколькими экспертизами, документы и контроль ответа. Интерфейс находится на `/letters`. Реальные письма не отправляются: действия фиксируют уже совершённые факты делопроизводства.

## Порядок работы

Черновик допускает неполные сведения. При регистрации обязательны тема, вид письма, внутренний номер, журнал и дата; у входящего нужен отправитель, у исходящего — хотя бы один адресат. Внутренний номер вводится вручную и не повторяется в одном журнале и году. Журнал может быть общим или относиться к отделу. Начальное заполнение не создаёт журналы учреждения и не присваивает номера.

После регистрации содержание заморожено. Можно назначить другого ответственного, подкрепить поздний файл, зафиксировать получение, отправку или доставку и вести контроль. Для исправления зарегистрированных реквизитов потребуется отдельная процедура; обычное сохранение черновика их не переписывает.

| Факт | Что подтверждает | Чего не означает |
| --- | --- | --- |
| Регистрация | Письмо учтено под внутренним номером | Не подтверждает отправку или неизвестное получение |
| Отправка | Конкретным адресатам отправлено в указанную дату | Не подтверждает доставку |
| Доставка | Конкретный адресат получил конкретную отправку | Не закрывает контроль автоматически |
| Входящий ответ | Есть отдельное связанное письмо | Частичный или дополнительный ответ не равен завершающему |
| Закрытие контроля | Ответственный принял решение по выбранному основанию | Не завершает экспертизу и не выдаёт материалы дела |

Первичная постановка на контроль требует регистрации письма. Неизвестный срок остаётся пустым; для известного нужны дата и основание. Срок не может предшествовать постановке на контроль. Изменение срока записывает отдельное событие текущей датой. Закрытие и возобновление сохраняют историю.

## Команды API

Префикс всех путей — `/api/v1`. Каждая изменяющая команда требует непустых `reason`, заголовка `Idempotency-Key` и, кроме создания, текущего `expected_version` письма. Ответ: `{event:{id},letter:LetterDTO}`. Создание возвращает 201, остальные успешные команды — 200.

Повтор с тем же ключом и содержанием возвращает прежний ID события и актуальную карточку. Новый вариант команды с тем же ключом или устаревшая версия дают 409. После утраты права прежний ключ не открывает доступ к записи.

Редактируемый черновик привязан к версии, из которой открыта форма. Обновление карточки не повышает эту версию незаметно. После конфликта пользователь сравнивает содержание с серверными сведениями и явно принимает новую версию для следующей попытки; потерянный ответ повторяется со старым ключом и телом.

Редакция заменяет доступные связи с работами. Уже существующие, но недоступные редактору связи сервер переносит в новую редакцию, не раскрывая их ID или количество. Пустой `material_id` из такой ограниченной карточки также сохраняет прежний недоступный материал. Заменять его другим материалом нельзя без доступа к прежнему: команда отклоняется целиком. Доступные связи по-прежнему можно явно убрать. Это исключение из полной замены необходимо, чтобы изменение темы не удаляло скрытые связи.

| Путь POST | Основные поля |
| --- | --- |
| `/letters/` | `direction`, `department_id`, `parent_id`, содержание |
| `/letters/{id}/draft/` | Полная новая редакция содержания |
| `/letters/{id}/attachments/` | `document_id` |
| `/letters/{id}/register/` | `journal_id`, `registration_number`, `registered_on` |
| `/letters/{id}/mark-sent/` | `sent_on`, `channel_id`, `recipient_ids`, `tracking`, `comment`, `evidence_document_id` |
| `/letters/{id}/mark-received/` | `received_on`, `evidence_document_id` |
| `/letters/{id}/mark-delivered/` | `dispatch_id`, `recipient_id`, `delivered_on`, `evidence_document_id` |
| `/letters/{id}/assign/` | `responsible_id` |
| `/letters/{id}/control/` | `opened_on`, `due_on`, `due_basis` |
| `/letters/{id}/control/deadline/` | `due_on`, `due_basis` |
| `/letters/{id}/control/close/` | `closed_on`, `closure_reason_id`, `reply_id`, `comment` |
| `/letters/{id}/control/reopen/` | `reopened_on`, `comment` |

Содержание: `kind_id`, `subject`, `body`, `sender_name`, `external_number`, `external_on`, `document_on`, `received_on`, `note`, `material_id`, `expertise_ids`, `reply_completeness`, `recipients:[{name,address,email}]`. Необязательные строки по умолчанию пустые, даты и ссылки — `null`, списки — пустые. Пропущенное поле новой редакции не подставляется из старой. Родитель задаётся только при создании: он должен быть зарегистрированным, доступным и противоположного направления. Полнота ответа — `partial`, `additional` или `final`.

## Чтение и выборки

`GET /letters/` возвращает обычную постраничную выборку полных карточек. Фильтры: `direction`, `state`, `kind_id`, `responsible_id`, `department_id`, `expertise_id`, `registered_from`, `registered_to`, `received_from`, `received_to`, `control_status`, `search`. Состояния письма — `draft`, `registered`, `partially_sent`, `sent`. Состояния контроля в фильтре — `open`, `closed`, `overdue`. Период получения использует только подтверждённое получение, не дату регистрации.

`GET /letters/{id}/` возвращает редакции, вложения, регистрацию, отправки, доставки, получение, историю ответственного, доступные ответы и контроль. Разрешённые команды перечислены в `allowed_actions`. Там же `control.view` обозначает право прочитать контроль именно этого письма независимо от существования задачи. При `control:null` и наличии этого признака контроль действительно не поставлен; без признака сведения недоступны, а не отсутствуют. Недоступный контроль не раскрывается, связанные чужие экспертизы не включаются в результат. Ограниченная ссылка на родителя или документ содержит только ID и `restricted:true`.

Варианты форм: `/letters/options/`, `/letters/work-options/?search=…`, `/letters/material-options/?search=…`. Справочники: `letter-kinds`, `letter-journals`, `dispatch-channels`, `control-closure-reasons`. Имена и активность меняются через существующий API справочников с проверкой версии. Направление и отдел журнала, а также правило основания контроля после создания не меняются обычным редактированием названия.

`GET /expertises/{id}/letters/` возвращает постраничный краткий список доступных связанных писем. `/me` объявляет возможность `supported_modules:["correspondence"]`; отсутствие этого признака скрывает раздел в Vue при работе со старым сервером.

## Основания закрытия контроля

Для `reply_sent` исходное письмо входящее. Нужен явно связанный завершающий исходящий ответ, зарегистрированный и фактически отправленный всем его адресатам к дате закрытия.

Для `reply_received` исходное письмо исходящее. Нужен явно связанный завершающий входящий ответ, зарегистрированный и с подтверждённой датой получения не позже закрытия. Частичные и дополнительные ответы остаются в переписке, но не удовлетворяют этим основаниям.

Основания `withdrawn`, `not_required`, `other` требуют пояснения самостоятельного решения. Наличие ответа само по себе контроль не закрывает. Завершение экспертизы также не меняет контроль письма.

## Документы и доступ

Регистрация и каждая отправка сохраняют ссылки на версии файлов, существовавшие в момент команды. Новый файл не становится отправленным задним числом. Бумажное письмо можно учитывать без выдуманной электронной копии. Подтверждение получения и доставки может иметь отдельный документ с зафиксированной версией.

Область `own` на чтение относится к текущему ответственному или текущему участнику доступной связанной экспертизы. На изменение — только к ответственному. Широкое право чтения не расширяет область подготовки или регистрации. Связь с одним материалом не открывает соседние экспертизы. Документ через письмо требует одновременно чтения письма и документа; это не даёт права загрузить новую версию чужого документа.

Новые шаблоны ролей содержат права переписки, но настроенные роли реальных сотрудников не расширяются автоматически. Для существующих учебных ролей предусмотрена явная команда `infra/local.py workflow-demo --enable-correspondence`. Она добавляет только новые права переписки эксперту и делопроизводителю, сохраняет остальные отозванные права и отказывается расширять роль, если в неё включён неучебный сотрудник.
