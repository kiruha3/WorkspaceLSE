## Реализованный путь

Эксперт с назначением и правом сохраняет отдельную редакцию результата. Полный СНДЗ не выводится из T, заключение с нерешёнными вопросами остаётся заключением. Для категории6 — акт исследования. Q/R/S/T nullable, отрицательные/дробные/противоречивые значения отклоняются, известные нули сохраняются. Сложность выше3 хранит точный уровень.

Причины полного СНДЗ, нерешённых вопросов и решения без исполнения — три разных справочника. `seed_result_catalogs` не переименовывает и не активирует отредактированные значения; новый неактивный выбор запрещён. Подтверждение распределения T требует точной суммы, other — пояснения. Произвольной «основной» причины не выбираем: вопрос владельцу о множественности полного СНДЗ пока без ответа.

Завершение требует текущую редакцию, фактическую дату и сохранённый файл соответствующего вида. Обычная сохранённая карточка без файла остаётся черновиком. Недостающие статистика, сложность и причины не подменяются нулями — это report_gaps. Решение без исполнения имеет собственный документ и дату; выдачу, фактический возврат и закрытие переписки не создаёт.

Корректировка с отдельным правом и основанием добавляет редакцию/подтверждение, не переоткрывает работу и не меняет тип закрытия. История и текущий ответственный сохраняются. Дата не раньше поступления и внесённых фактов производства; будущий срок исполнения не требует ждать его наступления. Счётчик прекращается на фактическом конце, фильтр работает до пагинации; у legacy с неизвестным концом не вычисляется фиктивный0. Открытая приостановка ограничена концом, resumed_on не выдуман.

Каждая команда имеет expected_version/Idempotency-Key, повтор сохраняет ID события и отдаёт свежую карточку/права/редакцию с текущей редакцией доступа к файлам. Receipt→Expertise lock общий с уточнением поступления; прошлые неподтверждённые/исправленные даты не запирают поступление навсегда.

## Решения и остаток

1. Пробелы отчётных сведений не запрещают закончить фактически документированную работу; цена — необходимость отдельной корректировки для полного отчёта.
2. Результат и подтверждение окончания append-only на уровне предметных команд; цена — дополнительные связи и история вместо прямой перезаписи. Прямое администраторское SQL не является поддерживаемым способом правки.
3. При окончании приостановленной работы не создаём resume; цена — интервал с пустым resumed_on у закрытой работы, визуально отличённый от продолжающейся паузы.
4. Множественность причин полного СНДЗ не предполагается: одна однозначная причина либо unknown/пояснение до ответа; цена — неполное распределение нескольких причин.

Далее: переписка/контроль запросов, комплект материалов/выдача, импорт исходного журнала с проверкой качества и все6 разделов15.1 с происхождением чисел. Завершённая демонстрация не доказывает готовность отчёта.

### Решения по отложенным на усмотрение вопросам

В дополнение к4 исходным решениям выше, по порядку итогового прохода:

1. Исторические неактивные причины допустимы в той же работе. Цена: если учреждение выберет current-only политику, потребуется согласованно ограничить UI/API.
2. Подтверждение закрепляет последнюю сохранённую FileVersion, корректировка явно переподтверждает последнюю выбранного документа. Цена: принятие произвольной более старой версии новым событием требует отдельного выбора/API.
3. Старые подтверждения связываются только с файлом, существовавшим на их timestamp, иначе unknown. Цена: ошибочные исторические времена требуют явной сверки, не догадки.
4. Переписка/выдача/импорт/15.1 остаются следующими срезами. Цена: вся система ещё не готова к эксплуатационной приёмке.
5. Решение о допустимых необязательных report_gaps подтверждено повторно. Цена: для полного отчёта понадобится корректировка.
6. Множественность причин СНДЗ/возврата не предполагается до ответа. Цена: несколько причин пока не разнесены структурно.
7. Открытая пауза у закрытого и сохранённый ответственный допустимы. Цена: потребители должны смотреть state/closure, а не только resumed_on.
8. Будущий due допускает раннее окончание. Цена: отчёт должен различать срок и факт, а не отвергать раннее окончание.
9. Legacy без closure остаётся unknown, обычная корректировка не придумывает подтверждение. Цена: отдельная сверка при импорте.
10. Черновик может быть без файла с поздним подкреплением. Цена: документ до подтверждения может измениться и требует проверки.
11. Потеря ответа создания Document может оставить лишние метаданные; существующий неидемпотентный endpoint не изменён. Цена: отдельное устранение orphan/idempotency остаётся, это не потеря сохранённого результата.
12. Новые demo-роли инициализируются актуальным шаблоном; действующие сохраняются без явного флага. Цена: существующим учебным ролям нужен opt-in.
13. Прямой SQL/admin не является поддержанным immutable-процессом, триггеры не добавлялись. Цена: привилегированная запись вне команд может нарушить инварианты.
14. Полная атомарность отзыва права посреди уже начатого запроса — общая политика, отдельного дефекта среза не установлено. Цена: уже разрешённый запрос может завершиться одновременно с отзывом.
15. Общая оптимизация запросов по длинной истории ждёт измерения. Цена: при росте нагрузки могут понадобиться отдельные страничные проекции.
