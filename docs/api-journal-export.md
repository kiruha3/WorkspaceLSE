# Выгрузка журнала из БД

`GET /api/v1/expertises/export.xlsx` возвращает XLSX с MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `Content-Disposition: attachment; filename="expertises-YYYY-MM-DD.xlsx"` и `Cache-Control: no-store`.

Необходимы одновременно `expertise.view` и существующее `expertise.export`. Записи ограничены пересечением обеих областей доступа: свои / отделы / учреждение. Для своих исторических записей учитываются подтверждённые участники до появления назначений нового учёта, как при просмотре реестра. При отсутствии любого права API возвращает 403, кнопка скрыта.

API использует тот же валидируемый фильтр, что и реестр: `search`, `department_id`, `specialty_id`, `employee_id`, `received_from`, `received_to`, `state`, `calendar_days_min`, `calendar_days_max`. Параметры пагинации не ограничивают файл. Кнопка передаёт применённые фильтры из URL, сохраняя значение `0`; несохранённое редактирование формы выборку не меняет. Загрузка начинается только по нажатию.

Первая вкладка «Лист1» повторяет три строки исходной шапки, объединения, подписи и порядок A–AB, включая колонки без заголовков. Добавлены закрепление E4, фильтр и повтор шапки при печати. Данные имеют тот же порядок, что реестр. Строки начинаются с четвёртой; пустая выборка возвращает шапку.

| Колонка | Значение из текущей БД |
|---|---|
| A | Исходный порядковый номер из `HistoricalWork.source_row.raw.A`; для новых записей порядковый номер выгрузки |
| B | `Expertise.registration_number` и известный `historical_number` в скобках, текст |
| C | `Receipt.received_at`, дата Excel |
| D | Текущее `Expertise.state`, подпись, распознаваемая парсером журнала |
| E | `WorkCaseDetails.authority_type.name`; если профиля дела ещё нет, `HistoricalWork.authority_type` |
| F | Текущий `authority_name` профиля дела либо истории; для новой записи без обоих — `Receipt.sender_name` |
| G | `official` профиля дела либо истории |
| H | `contact` профиля дела либо истории, текст |
| I | `basis_text` профиля дела либо истории |
| J | `WorkCaseDetails.case_number` и `case_description` через перевод строки; до профиля — историческое `case_description` |
| K | `inventory` профиля дела либо истории |
| L | Все действующие `ExpertAssignment.employee.full_name`; если назначений никогда не было — исторические участники либо `HistoricalWork.executor_raw` |
| M | Текущий `Specialty.code`, текст |
| N | `complexity_level` актуального результата либо исторического факта |
| O | `ResultRevision.kind` актуального результата либо `HistoricalWork.result_kind`, подпись журнала |
| P | Дата последнего `WorkClosure` для закрытой работы; до события нового учёта — актуальная историческая дата завершения/решения без исполнения. Для открытой работы пусто |
| Q | `questions` актуального результата либо исторического факта |
| R | `categorical` актуального результата либо исторического факта |
| S | `probable` актуального результата либо исторического факта |
| T | `unresolved` актуального результата либо исторического факта |
| U | Реальные распределения нерешённых вопросов: причина, количество, комментарий; до распределения — историческая текстовая причина и пометка `unresolved_note` |
| V | `HistoricalWork.amount`, если известна; в новой модели отдельной суммы нет |
| W | Исторический комментарий; при фактической выдаче нового учёта и доступе `issue.view` ко всем работам материала также способ, получатель, основание, трек и комментарий выдачи |
| X | Историческая отметка либо актуальная отметка «Выдано ДД.ММ.ГГГГ» по `MaterialIssue.issued_on` / `HistoricalWork.issued_on` |
| Y | Исходный `raw.Y`, отдельного нормализованного поля нет |
| Z | Календарные дни включительно по текущим датам: до окончания для закрытой работы, до даты выгрузки для открытой; неизвестная дата окончания даёт пустоту |
| AA | Вид результата, текущий номер и известная дата окончания, вычисленные значения без формулы |
| AB | Исходный `raw.AB`, отдельного нормализованного поля нет |

Профиль текущего дела и текущий результат авторитетны целиком: пустое поле не заменяется старой исходной ячейкой. При закрытии используется принятая версия результата, связанная с последним закрытием; черновик её не заменяет. Завершившиеся назначения не возрождают исторических исполнителей. Известная дата выдачи заменяет устаревшую самостоятельную отметку даты, сохраняя свободный комментарий. Названия и содержимое ограниченных документов выгрузка дополнительно не раскрывает.

Подробности фактической выдачи нового учёта доступны только по существующему `issue.view` с теми же правилами `issuance.material_queryset`, что API выдачи: все работы общего материала должны быть доступны для просмотра и просмотра выдачи. Исключение соседней работы фильтром не расширяет доступ к комплекту. Проверка выполняется одним запросом списка разрешённых материалов, без вычисления ролей на каждой строке. Сама известная дата выдачи остаётся фактом экспертизы, уже доступным через её просмотр.

Даты записываются датами Excel, счётчики — числами, неизвестные значения остаются пустыми, нули сохраняются. Номера/коды/контакты и любые исходные строковые значения записываются строками, включая начинающиеся на `=`, `+`, `-`, `@`: исполняемых формул нет. Сумма более 15 значащих цифр записывается точным десятичным текстом, поскольку Excel иначе округляет её.

Если собранная ячейка превышает предел Excel в 32767 символов или содержит недопустимые XML-символы, API возвращает 400 с номером экспертизы и буквой колонки. Экспорт не обрезает и не очищает данные незаметно. Допустимые табуляции и переводы строк, включая CR, сохраняются.

Файл повторно читается существующим парсером журнала при наличии обязательных фактов. Неизвестные бизнес-поля не заполняются вымышленными значениями, поэтому неполные записи сохраняют диагностические сообщения при повторном импорте. Состав исполнителей, номер дела, причины и реквизиты выдачи объединяются в доступных исходных текстовых ячейках: формат журнала не является полной резервной копией всех моделей. Шаблонные формулы Z/AA заменены текущими значениями; исходные формулы не исполняются и не копируются.

Экспорт не выполняет импорт, не записывает файлы на сервер, не меняет БД и не обращается к Google. Существующий отчётный загрузчик сохраняет своё запасное имя `15-1.xlsx`; реестр использует `expertises.xlsx`, если сервер не прислал имя.
