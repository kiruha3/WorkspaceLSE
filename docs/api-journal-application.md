# Сверка и подтверждённый перенос журнала

Исходная Google-таблица остаётся только для чтения. Команды работают с сохранённым снимком, а не с меняющимся документом Google. Пока оператор не выбрал строки и не подтвердил пакет, рабочие регистрации не создаются.

## Права и маршруты

Префикс `/api/v1`. Все маршруты требуют `imports.results.view` учреждения. Сохранение сопоставления дополнительно требует `imports.reconcile`, применение — `imports.apply`. Эти права не добавляются существующим реальным ролям автоматически. Для учебной роли есть явный `workflow-demo --enable-journal-application`; команда отказывается расширять роль с неучебным участником и не восстанавливает другие отозванные права.

| Маршрут | Назначение |
| --- | --- |
| GET `/imports/{batch}/reconciliation/` | Строки, классификация, предложения по точным кодам, сохранённый выбор |
| GET `/imports/reconciliation-options/` | Минимальные данные отделов, специальностей и сотрудников, без учётных записей и квалификаций |
| PUT `/imports/{batch}/rows/{row}/selection/` | Явно сохранить сопоставление строки |
| POST `/imports/{batch}/apply/` | Атомарно применить выбранный пакет |
| GET `/imports/applications/{id}/` | Протокол с настоящими ID рабочих экспертиз |

Сверка принимает `search`, `classification=new|unchanged|changed|invalid`, `page`. В ответе стандартная пагинация, `batch_id` и `summary` по всему снимку; фильтр не уменьшает общую сводку. Существующая работа показывается только кратко: id,registration_number,version. Неизвестная специальность и некорректное количество не исключают целую регистрацию. Недостоверные номер/поступление/состояние, дубли номеров и отсутствующий отдел блокируют применение.

## Сопоставление

Тело PUT: `expected_version,reason,department_id,specialty_id,employee_ids,appointment_nature,is_commission,complex_known,complex_group_key,statistics_confirmed`. Нужен `Idempotency-Key`. Для первого сохранения `expected_version:0`, затем текущая версия выбора. Неизвестные признаки — `null`, не «первичная», «единоличная» или ноль. Пустой ключ комплекса — `null`.

Код отдела совпадает с текущим номером; признанный код M — с кодом специальности. Отсутствующий M допускает неизвестную специальность либо её явный выбор с основанием. Неактивные справочные значения допустимы для истории, но не дают нового допуска. Комиссия требует не менее двух выбранных исторических участников; единоличная работа не подтверждается с несколькими текущими участниками. Подтверждение статистики требует заполненных и сходящихся Q/R/S/T. Сохранение не создаёт сотрудников, квалификаций, документов или экспертиз. После применения выбор неизменяем.

## Пакет

Тело POST: `reason,selections:[{row_id,expected_selection_version}]`, от 1 до 1000 различных строк одного снимка, плюс `Idempotency-Key`. Блокировки номеров, снимка, строк и справочников упорядочены. Ошибка одной строки откатывает весь пакет, включая аудит и квитанцию команды. Конфликт версии/номера даёт409, неверные сведения400, отсутствие нынешнего права403. Повтор успешной команды возвращает прежний протокол, не повторяя создание. Иное тело со старым ключом409; отзыв права действует и при повторе.

Ответ201: `{event:{id},application:{id,batch_id,created_at,created_count,existing_count,items:[{row_id,expertise_id,action}]}}`. `action` — created либо existing. Для той же уже применённой исходной строки новая команда может подтвердить существующую связь без повторного создания. Протокол хранит серверный список связей; первичная связь исходной строки с работой уникальна.

Новый снимок с уже имеющимся каноническим номером классифицируется unchanged/changed, но в этой create-only версии его применение даёт явный409. Подтверждённое обновление существующих работ и защита локальных исправлений — отдельное дальнейшее расширение, не скрытая перезапись.

## Что создаётся

Основные `Material`, `Receipt(status=historical)`, `Expertise(origin_kind=historical)` и типизированные `HistoricalWork`, а не отдельный архив. Материалы объединяются только явным ключом комплекса внутри одного снимка; у каждой специальности свой номер. Один ключ в другом снимке не объединяет материалы. Исторические сотрудники связываются только явно; это не новое назначение.

Неизвестные сведения остаются неизвестными. Противоречивая дата окончания или вид результата не становятся доверенными фактами. Никаких фиктивных `Document`, `FileVersion`, `ExpertAssignment`, `WorkClosure`, `Suspension`, `MaterialIssue` или квалификаций перенос не создаёт. Известная дата исторической выдачи блокирует новую выдачу; карточка выдачи помечает её происхождение `fact_origin:historical`, не выдаёт за новый серверный акт передачи.

Историческая работа до отдельного подтверждения основания и состава доступна для чтения, но не для новых назначений и производственных команд. Серверный15.1 и подтверждение продолжения исторической работы не считаются готовыми только по факту импорта.
