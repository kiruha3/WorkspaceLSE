## Действия и контракт

В карточке `/expertises/:id` доступны реализованные команды по текущим правам:

| POST `/api/v1/expertises/:id/…` | Поля кроме обязательных `expected_version`, `reason` | Результат |
| --- | --- | --- |
| `suspend/` | `suspended_on` | Открыть один интервал, состояние suspended |
| `resume/` | `resumed_on` | Закрыть открытый интервал, состояние in_progress |
| `deadline-events/` | `kind`, `recorded_on`, `due_on`, `document_id?` | Добавить факт срока, не затереть историю |

Всем нужен Idempotency-Key. Ответ `{event:{id},expertise:ExpertiseDTO}`: ID повторной команды стабилен, карточка и разрешённые действия читаются заново. Две команды одной версии не создают два интервала. Текущий исполнитель определяется активным назначением, должность начальника сама по себе не является экспертным полномочием; соседний номер комплекса не изменяется.

`kind`: initial — исходный срок/явное уточнение, request — запрос продления, agreement — согласованный срок. Запрос не меняет действующий срок. Для agreement нужен документ deadline_agreement/постановление/определение с бумажным оригиналом либо сохранённой копией; один запрос или пустая копия не подходят. Новые виды документов не заменяют постановление/определение при приёмке. Право чтения связанного документа не даёт право загружать его новые версии.

Реестр: `state`, `calendar_days_min`, `calendar_days_max` вместе с прежними фильтрами, до пагинации. Фильтры активных/рабочих дней не реализованы.

## Решения, принятые при реализации

1. Календарные дни включают день поступления и дату расчёта; закрытая пауза `[приостановка, возобновление)`, открытая включает дату расчёта. Метод виден в UI; это не юридический срок. Цена ошибки: нужна отдельная согласованная политика рабочего/правового календаря, текущие числа — наглядный календарный учёт.
2. Для закрытой работы без известного окончания счётчики неизвестны, а не растут до сегодня. Цена: видимый пробел до реализации/импорта достоверных дат результата.
3. Сроки добавляются фактами, последние выбираются по фактической дате события и времени регистрации при равенстве. Старый поздно внесённый ответ не вытесняет более новый факт, неизвестный исходный срок остаётся пустым. Цена: для исправления нужно явное событие, а не незаметная перезапись поля.
4. Команда требует и видимость работы, и конкретное право действия, поскольку возвращает полную свежую карточку. Цена: пользовательской роли только с действием нужно явно добавить право чтения для использования веб-команды.
