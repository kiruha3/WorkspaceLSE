# Архив документов экспертизы

Срез28.10.2026. Серверная реализация54f70a4; интерфейс и rollout проверяются отдельными этапами. Префикс всех путей `/api/v1`. PHP и Google не изменяются.

## Источники и версии

POST `/documents/` сохраняет `{kind,title,source_kind,department_id?,source_url?}`. Виды дополнены `case_material` («Материалы дела / иные документы»). Источник: `paper_original`, `uploaded_copy` или `external_link`. Для ссылки обязателен HTTP/HTTPS URL без логина/пароля; для других источников он пуст. Сервер при создании/чтении метаданных URL не запрашивает. Наличие ссылки не означает наличие принятого файла или бумажного оригинала.

GET `/documents/{id}/` возвращает прежние поля плюс `source_url`, версии содержат `relative_path`. POST `/documents/{id}/versions/` — multipart `{expected_version,file,relative_path?}`. Путь выбранной папки — только метаданные: нормализуются обратные слэши, запрещены абсолютные пути, диск, `..`, управляющие символы и другое basename. Хранение остаётся по UUID, не по присланному пути. И создание, и загрузка поддерживают прежние `Idempotency-Key`; пустые новые поля не добавляются к хэшу старой команды.

Для ссылочного документа можно явно загрузить сохранённую копию. В приёмке, основаниях сроков/3214-р/предыдущих заключений/причин сроков/годового плана и доказательствах переписки URL без файла отклоняется. Обычный бумажный оригинал остаётся допустимым там, где он был допустим; итог эксперта по-прежнему требует принятый сохранённый файл. Выдача сохраняет свой проверенный набор версий. Сам счёт не означает оплату.

## Дополнительные связи

`WorkDocumentLink`: UUID; FK экспертизы/Document; примечание; автор/дата; дата/автор/причина снятия связи. Активная пара уникальна. Это связь многие-ко-многим через отдельную таблицу, не копия Document/FileVersion для каждого номера. Снятая связь сохраняется как история; файл, другие связи и процессные основания не удаляются. Повторное прикрепление создаёт новую связь.

Новые независимые права `documents.link` и `documents.unlink` настраиваются в ролях. Области: собственные, отделы, учреждение. Автоматических grants нет. Обязательно право видеть работу и документ. Собственное участие: действующее назначение либо текущий участник перенесённой истории; для новой работы также зарегистрировавший её делопроизводитель. Автор массового импорта не становится владельцем всех импортированных работ. Связь даёт чтение через разрешённую текущую работу, не право загрузки новой версии чужого документа.

Команды используют блокировки материал→поступление→работа, ожидаемую версию, текущие права, ключ повтора и аудит. Успех увеличивает версию работы, но не меняет состояние/основание/принятый итог/факт выдачи. Архивное дополнение возможно и после выдачи; это не коррекция прошлого события.

## Архив API

| Метод и путь | Назначение |
|---|---|
| GET `/expertises/{id}/documents/` | Разрешённый объединённый список, фильтры `search`, `kind`, `page` |
| GET `/expertises/{id}/documents/options/` | Разрешённый поиск существующих документов для прикрепления; требует link+view |
| POST `/expertises/{id}/documents/` | `{expected_version,document_id,note?,reason}` — дополнительная связь |
| POST `/expertises/{id}/documents/{link_id}/detach/` | `{expected_version,reason}` — снять только эту дополнительную связь |

GET возвращает `{count,next,previous,results,context,can_link,can_unlink,can_create,document_kinds,detached_links}`. `context`: `{id,registration_number,version,state,material:{id},department:{id,code,name}}`. Одна строка `results` — `{document,origins,extra_links}`. Источник — `{kind,id,label,...}`; для принятого события **есть** `accepted_version_id`, в том числе явный null. Отсутствующее поле означает общий/непринятый контекст. UI не подставляет latest вместо принятого V1 или неизвестного принятого файла. Общий просмотр других версий выбирается явно.

Агрегируются существующие типизированные основания поступления, события сроков, редакции результата и причины вопросов, окончания,3214-р, предыдущие заключения, доказательства сроков, текущая доступная переписка работы, её комплект/принятые файлы и разрешённое подтверждение выдачи, дополнительные связи. Соседние номера и старая редакция письма не раскрываются. Опись/текст журнала не превращаются в физический файл.

Команды возвращают `{event:{id},library:...}`. Повтор прежнего ключа возвращает прежнее событие и свежий список, не реактивирует снятую связь. Новый ключ для уже активной пары —409; чужая связь —404; устаревшая версия —409; нет текущего права —403. Ошибка формирования ответа тоже откатывает команду. История снятых связей содержит полный Document только при сохранившемся текущем доступе, иначе `{id,restricted:true}`; файлы при скачивании повторно проверяют права.

## Интерфейс и границы

Маршрут `/expertises/:id/documents`, ссылка из рабочей карточки. Capability `/me/`: `work_documents`. Чтение, добавление нового/существующего/URL, выбранная папка или несколько файлов, история, версии. Для папки максимум100 файлов за один выбор; последовательная обработка metadata→file→link с сохранением ключей и подтверждённых успешных строк. Это не транзакция на всю папку: частичный успех явно показан. После403/409/потери ответа ввод/файл сохраняется; версия работы и версия Document принимаются раздельно и явно.

Внешний просмотр запускается отдельной кнопкой, sandbox без scripts, без referrer; отдельное открытие источника доступно при запрете встраивания. Сохранённые PDF/изображения показываются внутри веба. Офисные файлы пока честно предлагаются для скачивания. Управляемые постоянные папки, серверное обновление URL/конвертер, supplements/replaces, полная ролевaя приёмка и официальный15.1 остаются общей целью.
