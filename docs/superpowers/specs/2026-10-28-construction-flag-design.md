Владелец прямо поручил сделать флаг при регистрации и редактировании;3214-р относится только к16.1/16.2 с этой отметкой. Источник: docs/owner-report-decisions-2026-10-28.md. Уже выбран автономный inline способ без нового worktree/push и повторного согласования технической реализации.

Использовать существующий `WorkCaseDetails.decree3214`, не создавать дублирующий признак: это сохраняет ссылки, версии и историю. Отдельное новое поле потребовало бы синхронизировать две противоречащие истины. UI показывает чекбокс только для16.1/16.2; отсутствие отметки не включает работу в графу3214-р и не блокирует регистрацию/отчёт. Старые строки не заполняются массово.

Регистрация принимает необязательный bool `decree3214`. Только если поле передано, под существующей транзакцией создаются профиль/редакция с явным значением и регистрационным автором; старая форма без поля сохраняет прежний контракт. True для иной специальности отклоняется атомарно. Назначений/прав автоматически не добавляется. Форма сбрасывает отметку при выборе иной специальности, повтор команды не дублирует профиль.

Редактирование использует существующий case-details API/права/expected_version/idempotency. Файл и пояснение для отметки необязательны; если файл выбран, его доступ/наличие по-прежнему проверяются. БД ослабляет только условие обязательного подтверждения приtrue, существующие записи сохраняются. False/null не должны иметь оставшиеся реквизиты отметки.
