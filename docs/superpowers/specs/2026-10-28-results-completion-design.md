# Результат, завершение и решение без исполнения

Продолжение общей спецификации §5.4/8 после8f78697. Владелец поручил продолжать без повторных согласований уже выбранной архитектуры. Django/PostgreSQL + Vue, самостоятельный ais-lse, старые источники не изменяются, push/merge нет. Это следующий необходимый путь к15.1, не замена оставшихся переписки/выдачи/импорта/отчёта.

## Подход и границы

Выбран встроенный блок результата в карточке с отдельными командами: черновик, завершить, решить без исполнения, исправить закрытое. Общий PATCH состояния теряет проверки и происхождение; отдельный микросервис здесь не нужен. Подготовленный документ прикрепляется, редактор текста заключения и юридическая ЭП не создаются. Нет нового согласования начальником. Backend реализуется inline, Vue независимо по договорённому DTO, одно свежее ревью всего среза.

Начальник-эксперт действует по назначению/роли как любой эксперт. Видимость работы и конкретное действие обязательны. Новые `expertise.result.draft` и `expertise.return_without_execution` дополняют существующие complete/closed.correct; должность сама прав не даёт. Реальные/отредактированные роли автоматически не расширяются. Явный demo-флаг добавляет новые права только учебной роли, если у неё нет реальных участников.

## Факты и история

- Каждый save создаёт неизменяемую типизированную ResultRevision с порядковым номером в работе, автором, временем и основанием; прежнее не затирается. Черновик не завершает работу.
- Виды результата: expert_conclusion, sndz для категорий1–5; research_act для6. Без исполнения — отдельная WorkClosure, не четвёртый вид заключения.
- Q/R/S/T — вопросы / категорические / вероятные / нерешённые. Значения null либо неотрицательные целые. Неизвестное не выводится в ноль. Все известные части не превышают Q; когда все четыре известны, сумма обязана совпадать. Подтверждение полноты требует всех четырёх и равенства.
- Распределение нерешённых вопросов — отдельные строки reason/count/comment/document, без повторения причины. При подтверждении полноты сумма равна T; до подтверждения не превышает известное T. Для other нужно пояснение. Полный СНДЗ автоматически не создаёт распределение T.
- Причины полного СНДЗ, нерешённых вопросов и возврата — три отдельных расширяемых справочника из предоставленного бланка. Их коды не координаты Excel; названия/активность меняются по существующему references.manage. Использованные ссылки PROTECT, история выбора сохраняется. Новый выбор неактивного запрещён; сохранение прежнего выбранного значения той же работы возможно. Предзаполнение идемпотентно, не переименовывает и не активирует отредактированное.
- Неподтверждённая множественность причин полного СНДЗ/возврата не выбирается молча. Сейчас можно внести одну однозначную причину, неизвестную оставить пустой с пояснением; несколько не сводятся к случайной основной. Владельцу задан отдельный вопрос; возможный ответ уточняет эту часть до её реализации.
- Сложность хранится числом >=1 либо null; >3 остаётся точным числом и относится к группе выше3, не обрезается до3. Семантические виды результата/группы сложности не произвольные состояния процесса.

## Завершение и корректировка

Технический выбор: завершение подтверждает достоверный итог, не полноту всей статистики. Обязательны текущая редакция допустимого вида, дата окончания и сохранённый файл документа соответствующего вида. Бумажная метка без файла не изображает подкреплённый результат. Неизвестные статистика/причины/сложность остаются явными report_gaps, не фиктивными нулями и не скрытым полным отчётом. Это позволяет честно закончить работу и затем исправить сведения отдельным правом.

WorkClosure — неизменяемая история подтверждений: completed либо without_execution, дата, итоговая редакция или документ решения/причина возврата, автор и основание. Последняя определяет текущий конец производства. Решение без исполнения не устанавливает выдачу/фактический возврат. Переписка не закрывается автоматически. Назначения не прекращаются молча: ответственный за закрытую работу остаётся определён, производство уже закрыто состоянием.

Фактические даты от поступления до сегодня учреждения; конец не раньше уже внесённых приостановок/возобновлений и событий сроков. Будущий срок исполнения не ограничивает дату окончания. При завершении suspended не выдумывается resume: открытый интервал ограничивается реальным окончанием при расчёте и так подписан в UI. Дни считаются до окончания, не растут после; у legacy без подтверждённого окончания остаётся null.

Корректировка closed.correct не переоткрывает работу, не меняет completed на without_execution или обратно, требует основания и создаёт новую редакцию/подтверждение. История остаётся доступной. Обычный complete/result.draft не редактирует закрытое. Получение чужого файла через связь не даёт права его изменять.

Все изменяющие команды с expected_version + Idempotency-Key, блокировка Receipt→Expertise→evidence/reference, факт+версия+аудит атомарно; cache хранит только id события, карточка и документы проектируются заново по текущим правам. Уточнение даты поступления не может перейти за действующее подтверждённое окончание; непроверенная дата черновика при уточнении пересчитывает readiness, не подменяет подтверждение.

## Договор DTO

Expertise дополнен result:null|ResultRevisionDTO, result_history:[], closure:null|ClosureDTO, closure_history:[], result_readiness:{completion_blockers:Issue[],report_gaps:Issue[]}. Issue={code,field,message}.

ResultRevisionDTO: id,number,kind:null|expert_conclusion|research_act|sndz,completed_on:null|string,document:DocumentLink,complexity_level:null|integer,questions/categorical/probable/unresolved:null|integer,statistics_complete:boolean,sndz_reason:null|Reference,sndz_comment:string,unresolved_allocations:[{reason:Reference,count:number,comment:string,document:DocumentLink}],allocations_complete:boolean,note:string,actor:{id,full_name},created_at,reason. Reference — существующие id/code/name/is_active/version. ClosureDTO: id,number,kind:completed|without_execution,ended_on,document:DocumentLink,result_id:null|string,return_reason:null|Reference,comment,actor,created_at,reason.

POST result/ — expected_version,reason + все поля результата, но document_id/sndz_reason_id; allocations используют reason_id/document_id. null и пустые списки передаются явно, bool по умолчаниюfalse. POST complete/ — expected_version,reason,result_id (последняя редакция). POST return-without-execution/ — expected_version,reason,decided_on,document_id,return_reason_id:null|UUID,comment. POST correct/ — expected_version,reason,correction_kind:result|return; для result вложенный result:{те же поля без версии/основания}, для return остальные поля решения. Ответ всех `{event:{id},expertise:ExpertiseDTO}`. GET result-options/ — result_kinds:[{code,name}],complexity_groups:[{code,name}],sndz_reasons/unresolved_reasons/return_reasons:Reference[].

Новые Document.kind: expert_conclusion,research_act,sndz,return_decision; они не заменяют минимум основания поступления. В карточке сохраняются подготовленный файл, поля и ключ при403/409/потере ответа; повтор не блокируется новым min даты браузера, нормализованные пробелы не создают новый факт. Исправленный факт не переоткрывает видимость бывшему исполнителю.

Production добавляет counted_through:null|string; as_of остаётся датой расчёта. Реестр считает/фильтрует календарные дни для закрытых с известным концом до пагинации; неизвестный конец не равен0. Состояние и фильтры сохраняются в URL.
