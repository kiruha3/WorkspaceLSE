# Обновление реестра с перечнем принимаемых изменений

Согласовано в чате 29.10.2026: владелец хочет самостоятельно запускать обновление БД из свежей таблицы либо файла и видеть перечень того, что принять. Ранее предложенный сценарий «сначала перечень, затем подтверждение» принят; дополнительных обсуждений исполнения не требуется.

## Назначение и границы

В реестре появляются действия «Обновить из таблицы» и «Загрузить Excel/CSV». Первое читает настроенный Google-лист, второе сохраняет выбранный файл существующим импортёром. Исходники не изменяются. Оба действия открывают единый просмотр новых и изменённых регистраций. Фильтр реестра не ограничивает импорт.

Рабочие экспертизы изменяются только после нажатия «Применить выбранное». Для новой записи выбирается вся регистрация, для существующей — отдельные изменённые поля. Показываются номер, поле, значение БД, значение таблицы; ручное расхождение отмечается отдельно. Все флажки первоначально выключены. Кнопка выбора неконфликтных изменений не выбирает конфликтные поля.

## Подход

Используется текущий Django/Vue импортёр: неизменяемые снимки, точное сопоставление ссылок, версионность, аудит и ключ повторной попытки. Полная перезапись реестра не подходит: она стирает ручные правки и создаёт риск дублей. Старый подробный экран сопоставления остаётся доступным для неоднозначных строк.

Новый просмотр и атомарное применение — небольшая надстройка, не новый механизм загрузки файлов. Номера, исторические коды отделов, нынешние отделы сотрудников и существующие бизнес-правила не переопределяются.

## Данные и конфликты

- Новые ссылки подбираются только по точному существующему коду/имени. Нераспознанный непустой исполнитель требует ручного сопоставления; сотрудник не создаётся автоматически. Если исполнитель не изменился, сохраняется прежний подтверждённый состав.
- Показываются поля, отличающиеся и от БД, и от последнего принятого значения именно этого поля. Ручные изменения других полей сохраняются. Непринятые предложения не исчезают: их можно принять позднее из того же снимка или после повторного чтения таблицы.
- Ручное изменение исторического поля не запрещает принять другое поле. Принять конфликтное поле можно только явным флажком рядом с его значениями.
- Продолженные в новом учёте работы, события производства/выдачи и отдельные ручные сведения дела/классификации/сроков не переписываются этим действием. Причина показывается и предлагается открыть карточку/подробную сверку. Переработка штатного документооборота не входит в задачу.
- Для исходных Q/R/S/T, отсутствующих дат и специальностей не выдумываются значения. Выбранное пустое поле означает явное принятие пустого значения, а не ноль.
- Применяются только выбранные строки и поля; всё подтверждение атомарно. Конкурентное изменение работы, источника, справочников или сопоставления требует обновить перечень. Потерянный ответ повторяется с прежним ключом и неизменным пакетом.
- Согласованность проверяется по итоговому сочетанию выбранных и оставленных значений: даты не могут оказаться раньше поступления, подтверждённые Q/R/S/T и распределение нерешённых вопросов не должны разойтись. Ошибка объясняет, какие связанные поля принять вместе либо уточнить в карточке. Отсутствующие исторические значения не становятся обязательными.
- База принятия восстанавливается из исходного переноса и неизменяемых протоколов. Частичный протокол меняет базу только принятых полей; полное «после» остаётся аудитом, но не подтверждает остальные поля. Повторное частичное принятие сохраняет прежнее сопоставление строки и создаёт новый протокол, не дублируя строку источника.
- Старые API полного переноса/обновления сохраняют прежнюю семантику. Новый выбор полей используется только новым API подтверждения.

## Проверка и поставка

Тестами проверяются отсутствие записи при просмотре, точные ссылки, выбор отдельных полей, конфликты, сохранение ручных правок, атомарность, повтор без дублей, устаревшие версии и права. Фронтенд проверяется отдельно на пустой список, запрет отправки без выбора, файл/Google, отображение ошибок и неизменность повторной попытки. На рабочей БД проверяется только чтение: реальные 478 записей во время разработки не обновляются. Выгрузка в XLSX остаётся отдельным следующим шагом.
