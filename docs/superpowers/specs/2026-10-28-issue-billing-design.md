# Выдача КоАП/исследований и счёт платной работы

## Требование и границы

Владелец 28.10.2026 подтвердил обычный комплект категории4: материалы, подписка эксперта, сопроводительное, заключение. Для категории6 итог — акт экспертного исследования. Для любой платной работы, включая акт, дополнительно счёт. Ранее утверждённые уведомление для1/5 и счёт для2/3 сохраняются. Наличие счёта не подтверждает оплату; предоплата не вводится как условие выдачи. Полный СНДЗ, возврат, число подписок комиссии и частичная выдача не утверждены этим ответом.

Продолжается ранее выбранное владельцем автономное inline исполнение без повторных согласований. Django/Vue/PostgreSQL сохраняются, без новых зависимостей/прав/grants, PHP и Google не меняются, push/merge/worktree не делать. Реальные факты платности не угадывать и не заполнять массово.

## Подходы и выбор исполнителя

Выводить платность из суммы/категории нельзя: сумма и платность не одно и то же. Отдельный финансовый регистр работы потребовал бы новой команды/прав для корректировки уже оконченной работы и вышел бы за учёт комплекта. Выбран явный nullable `is_paid` по каждой работе **в редакции комплекта выдачи**: его заполняет уже уполномоченный `issue.prepare` делопроизводитель, проверка/выдача используют ту же редакцию. Это выбор исполнителя, не новое утверждение владельца о бухгалтерии. Первоначальное предположение разместить поле в общих сведениях дела уточнено после чтения текущей политики закрытых работ.

## Данные и контракт

Новая `PackageWorkBilling`: revision FK PROTECT/related_name=billing, expertise FK PROTECT, is_paid nullable Boolean без defaultFalse; уникальная пара revision/expertise. Миграция только добавляет таблицу, не выводит значения для существующих работ. Старая редакция остаётся неизменной.

POST создания/черновика принимает необязательное `billing: [{expertise_id: UUID,is_paid: true|false|null}]`. Записи обновляют платность указанных работ, остальные значения переносятся из предыдущей редакции. Отсутствующий/пустой список не стирает сведения старого клиента. Явный null возвращает неизвестное. Дубли и работы другого материала —400 без orphan-редакций, аудита/commandreceipt. Проверки прав, версии, idempotency и запрет изменений после выдачи остаются текущими. На каждый новый ввод создаётся обычная новая редакция, поэтому предыдущая проверка автоматически устаревает.

DTO content/content_history содержит billing; works содержит эффективный is_paid текущей редакции. Одна исходная редакция для read/requirements, без вычисления платности по исторической сумме. Обычное завершение с заключением допустимо в1..5, категория6 требует research_act. Подписка+сопроводительное обязательны; уведомление добавляется для1/5; счёт для2/3 либо is_paid=True ровно один раз. Материалы описываются существующим обязательным materials_description, принятый итог — существующий WorkClosure/файл. При is_paid=None у поддерживаемого комплекта blocker `billing_unknown`, черновик разрешён, check/issue запрещены до уточнения. Неподтверждённые и несовместимые виды результата остаются `policy_unconfirmed`, комиссия отдельно.

## Интерфейс

В редакторе существующего комплекта по каждой работе select «Платность работы»: «Не уточнено», «Не платная», «Платная — требуется счёт». В просмотре — явное значение, требования и недостающие части от сервера. Сохранение неизвестного черновика допустимо. История редакций показывает сохранённую платность. Уведомление: счёт не подтверждает оплату. Во время потери ответа повторяется тот же пакет/ключ, 403/409 не стирают выбор; новый GET не затирает редактор. Первоначальный черновик сначала получает работы с сервера, затем пользователь заполняет их сведения, как уже происходит с документами.
