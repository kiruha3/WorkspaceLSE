# Фактический отдел и связь с сотрудником при переносе

Последнее уточнение владельца28.10.2026 имеет приоритет: «если раньше1пусть будет один», номера остаются, экспертизы должны быть связаны с людьми. Схема определения отдела по специальности владельцем ОТКЛОНЕНА и не применяется. Цель — реальный перенос472регистраций без переписывания истории.

- `Expertise.department` и `Receipt.department` сохраняют ФАКТИЧЕСКИЙ отдел экспертизы из номера. Для старых258работ это1, не3/4. Нынешние отделы людей отдельно хранятся в EmployeeOrgAssignment и не изменяются.
- Код регистрации уже хранится в неизменяемом `registration_number`; новый read-only `registration_department_code` разбирается из него. Дополнительная копия кода и миграция БД не нужны.
- Добавляется историческая неактивная справочная запись отдела1 без выдуманного наименования подразделения: «Отдел1 (исторический код)». Это неАУП и не новое штатное назначение. Импорт по-прежнему требует точного совпадения фактического отдела и кода номера.
- Нативная регистрация новых экспертиз по-прежнему требует совпадения выбранного отдела и создаваемого номера. Правило не ослабляется.
- `historical_facts.department_code` отражает код номера; отдельное поле текущего отдела экспертизы не выдумывается. Прежний номер другой организации остаётся отдельным `historical_number`.
- На сверке, в редакторе и карточке показывается фактический отдел экспертизы. Сохранённое сопоставление `mapped_department` видно читателю без кадрового optionsendpoint. Редактор не предлагает подменить отдел другим кодом.
- Специальность M, номера, состояния, исходные строки, допуски и назначения этим исправлением не меняются. Для известной M сохраняется проверка точного кода.

## Решения

Выбран существующий FK фактического отдела + производный код регистрации. История работы не определяется нынешним отделом её эксперта. Дополнительная копия кода могла бы разойтись с номером.

## Реальный перенос

Используются существующие проверяемые команды сопоставления и применения. Номера, отделы, даты поступления, состояния и кодыM берутся из472строк сохранённого Google-снимка. Люди связываются с имеющимися10сотрудниками по ФИО;5явных отметок передачи относятся к адресату (ранее подтверждено владельцем), строки с двумя людьми сохраняют двух исторических участников без выдуманной комиссионности. В3пустых строках исполнитель и специальность остаются неизвестны. Не создаются новые допуски, файлы, активные назначения, окончания/приостановки или состав комплексов. Перед применением — локальный pg_dump; после — сверка472номеров/отделов/строк/участников и открытие реестра.
