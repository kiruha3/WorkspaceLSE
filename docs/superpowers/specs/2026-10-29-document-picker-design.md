# Единый выбор документа без ручного кода

Владелец выбрал предложенный в чате вариант: поиск по документам + «Добавить новый» рядом. Цель — выбирать по понятному названию, а не копировать UUID. На примере работы в производстве показать итог без сохранения её данных.

## Подход

Один переиспользуемый DocumentPicker: поиск, постраничный список доступных документов, выбранный документ с предпросмотром, создание через существующую BasisDocumentForm. Отдельная страница выбора заставляла бы покидать несохранённую карточку; сохранение разрозненных полей кода не решает запрос. Выбран единый встроенный вариант.

- Заменить ручные ID в подтверждении импортированной работы (основание и итог), сведениях дела, предыдущих заключениях, подтверждениях сроков и годовом плане. Тем же компонентом оформлять выбор основного результата.
- Поиск только среди доступных по существующему documents.view; новые права не выдавать. Добавление доступно только с documents.upload. Ограничения вида документа и сохранённого файла в конкретном процессе остаются прежними.
- Добавить read-only GET /documents/: поиск по названию/имени файла, фильтр видов, пагинация. Применять существующую can_document до выдачи результата и подсчёта. Без новых таблиц и миграций.
- Выбор, поиск, открытие создания не сохраняют бизнес-факт. Создание и загрузка выполняются при штатном сохранении родительской формы; существующий механизм повторной попытки и конфликта версии файлов сохраняется.
- Сохранять выбранный документ при смене страницы поиска. Не выбирать первую строку автоматически; запоздалые результаты/проверки не заменяют новый выбор. При смене вида результата не оставлять неподходящий документ.
- Не терять заполненную форму нового документа при переходе к поиску без предупреждения. Не менять обязательность документов, статусы экспертиз, правила завершения, роли, существующие файлы и рабочие записи.
- Не создавать копию документа при выборе существующего. Прежние два изменения сворачивания напоминаний не включать в коммит. Без push.
