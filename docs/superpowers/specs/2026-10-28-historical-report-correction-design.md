# Уточнение отчётных сведений старой закрытой работы

Продолжение цели рабочего процесса. Сейчас HistoricalFacts только читает импорт; неизвестные Q/R/S/T, причины, даты и специальность нельзя дополнить без фиктивного нового окончания. Предыдущий этап подключил причины к15.1; теперь нужен нормальный ввод этих фактов.

## Выбранный подход

Исправлять исходный снимок — потерять доказательство источника; отдельный теневой overlay только для отчёта — разойтись с календарными сроками и карточкой. Выбор исполнителя: текущие типизированные HistoricalWork/специальность обновляются атомарно, отдельная неизменяемая HistoricalCorrection сохраняет полный before/after. Исходные raw/facts/файлы не меняются. Это ретроспективное уточнение, не новая экспертиза, выдача или подтверждение юридически значимого документа.

## Данные и команда

- HistoricalWork получает sndz_reason/sndz_comment, allocations_complete/report_note, return_reason/return_comment. HistoricalUnresolvedAllocation хранит reason/count/comment/document по образцу UnresolvedAllocation; число положительно, причина уникальна в текущем распределении. HistoricalCorrection: history,number,actor,created_at,reason,before,after; уникальный номер редакции. Старые строки получают только неизвестные/пустые defaults, без автоматической классификации.
- `POST /expertises/<id>/history-report/` требует Idempotency-Key и `{expected_version,reason,specialty_id,correction_kind,result?|return_data?}`. correction_kind=result дляcompleted, return дляwithout_execution. Result — существующая семантика ResultData без главногоdocument_id: kind,completed_on,complexity,Q/R/S/T,statistics_complete,sndz_reason_id,sndz_comment,unresolved_allocations,allocations_complete,note. Return_data — decided_on|null,return_reason_id|null,comment. Неизвестные значения можно оставить неизвестными; пробел не равен0. Основание обязательно.
- Только origin_kind=historical, operational=False и закрытое состояние, без нативных назначений/приостановок/сроков/результатов/закрытий/комплекта, включая черновик. Историческая дата выдачи не запрещает исправление метаданных; физическая выдача не редактируется. Операционную работу исправляют прежними командами.
- Не менять номер, состояние, фактический отдел, поступление, исполнителей, исходный снимок и issued_on. Специальность выбирается явно, без определения из нынешнего отдела/роли человека. Для комплекса действует существующая уникальность специальности.
- Числа, баланс и причины проверяются общим ResultData; kind соответствует категории номера. Известная дата не раньше поступления и не позже сегодняшнего дня. Для иной причины нужно пояснение. Новый неактивный справочник выбрать нельзя; уже использованный в этой истории можно сохранить/восстановить. Подтверждающий документ распределения требует обычного права documents.view.
- Material→Receipt→Expertise→HistoricalWork блокируются в общем порядке; затем все документы→справочники в стабильном порядке. Версия проверяется после ожидания. Audit и HistoricalCorrection пишутся одной транзакцией, work.version+1. Повтор ключа возвращает первоначальную редакцию без дублей; права проверяются и на повторе. Ошибка откатывает всё.
- Google-синхронизация после ручной HistoricalCorrection блокируется с объяснением даже при исправлении только причин: новый снимок не затирает ручное уточнение.

## Права и интерфейс

Используется существующее `expertise.closed.correct` плюс expertise.view. Никаких новых прав/учётных записей/выдачи прав в рабочей БД. В режиме own подтверждённый HistoricalParticipant без нативных назначений считается владельцем только для этого ретроспективного действия; это не право назначать/завершать нативную работу. Иначе действуют текущие scopes department/institution. Вопрос владельцу об ответственных ролях задан отдельно, реализация назначения прав не предполагает.

Карточка показывает текущие уточнённые факты, отчётные причины и историю before→after с автором/основанием. Кнопка доступна только по серверному allowed_actions; GET options возвращает причины/специальности в области доступной карточки, не кадровый каталог. Форма содержит явные неизвестные, подтверждения полноты, причины, дату и основание. Потерянный ответ фиксирует пакет/ключ и блокирует редактирование; конфликт версии сохраняет ввод и предлагает явно принять новую версию; смена карточки не переносит черновик/ответ. Подпись причины СНДЗ включает отказ в дополнении материалов, в том числе в отчётном заголовке.

Registry читает текущие структурированные причины/распределения HistoricalWork одним SELECT. Последнее нативное закрытие по-прежнему имеет приоритет. Изменение дат/статистики/причин меняет fingerprint и Excel; календарные сроки используют те же типизированные даты. Исходный журнал остаётся отдельным неизменённым источником сравнения.

После ревью: определённый ответ409 завершает неопределённость попытки, сохраняя ввод для явного принятия свежей версии. Доступ к подтверждающим документам проверяется и при возврате сохранённой квитанции. Подтверждение нового учёта предварительно заполняет причины/пояснения/распределения из текущей истории для явного подтверждения, сохраняет её использованные неактивные ссылки без допуска новых. Исторические before/after и причины остаются читаемыми после перехода, редактор при этом недоступен.

Для настоящей браузерной проверки допускаются2 явно synthetic historical demo (Material.is_demo=True) с исполнителем demo.expert2, у которого уже есть own closed.correct; создание атомарно, с аудитом, не из Google. Никаких новых live grants. Эти2 работы не попадают в15.1; все реальные цифры сохраняются. Без PHP/Google writes/push/merge/worktree/новых пакетов/дополнительных серверов. Полная цель остаётся активной.
