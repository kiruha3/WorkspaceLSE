# Настройка источника Google-журнала

Пользователь поручил добавить редактирование ссылки и листа через сайт; кнопку и само действие разрешает только отдельное право роли. Исполнение — в текущем checkout без push и без дополнительных обсуждений штатных деталей.

## Решение

Одна настройка учреждения в PostgreSQL, с версией и аудитом. Пока сохранённой настройки нет, используется прежняя конфигурация сервера. После сохранения новые чтения используют БД без перезапуска; старые снимки не меняются. PHP, Google-таблица и экспертизы не изменяются.

Форма `/imports/source-settings`: ссылка Google Sheets, числовой gid листа, название листа. Вставка ссылки с gid заполняет поле gid; отдельно введённое значение gid является окончательным выбором. Название листа — подпись, настоящий лист определяется gid. Сохранение не читает Google и не запускает импорт. Дополнительная проверка свежего журнала остаётся прежней отдельной операцией.

`imports.source.manage` («Настраивать источник Google-таблицы») действует только на учреждение. Видимость ссылок, доступ к форме, GET/PUT настроек и повтор команды проверяют это право; superuser без активного ролевого назначения не получает обход. Право появляется в существующем редакторе ролей. Прежнее разрешение владельца дать setup все права распространяется на это действие; другим сотрудникам оно автоматически не назначается.

Ссылки «Настроить источник» доступны в реестре и в блоке Google-источника. Форма работает и для менеджера источника без права запускать импорт. Отзыв права скрывает действие, а сервер повторно проверяет полномочия. Ввод не теряется при ошибках; при неопределённом ответе редактирование блокируется, повтор отправляет прежний пакет и ключ. Устаревшая версия — 409 без перезаписи.

## Интерфейсы

Прежний GET `/imports/google-source/` сохраняет форму ответа и получает действующий источник из БД с fallback на конфигурацию. Новый GET `/imports/google-source/settings/` возвращает `{url,gid,sheet_name,version}`; PUT принимает те же поля с `expected_version` вместо `version` и `Idempotency-Key`, возвращает сохранённые значения плюс `event.id`. На пустой настройке version=0. При сохранении разрешена только корректная HTTPS-ссылка docs.google.com/spreadsheets/d/<id>, gid — 1–10 цифр, название — 1–255 символов. Ссылка хранится канонически. Старые URL снимков и номера работ не меняются.

## Рассмотренные подходы

Редактировать JSON конфигурации — по-прежнему требует перезапуска и смешивает настройки с секретами. Хранить ссылку только в браузере — даёт разные источники сотрудникам и не обеспечивает контроль сервером. Выбрана настройка учреждения в БД: обычная ролевая команда, аудит, версия, совместимость с текущим запуском.

## Проверки

Отказ без права/после его отзыва, повреждённая ссылка, отсутствие сети при сохранении, смена источника без рестарта, неизменность бизнес-записей, повтор ключа, устаревшая версия, независимость старых снимков; frontend — видимость, управление gid, сохранение, отмена/ошибки, неизменный повтор и отзыв права.
