# Выбор способа подсчёта причин длительности

Владелец сначала выбрал учёт каждой указанной причины, затем уточнил: «по опции лучше считать» и явно подтвердил: «Да, переключатель; по умолчанию все». Реализуем выбор на форме отчёта, не изменение фактов экспертизы.

## Подходы

Глобальная настройка требует менять конфигурацию и не видна пользователю. Сохранённая политика учреждения требует отдельного управления и согласования. Выбор при расчёте — минимальное решение для сравнения, явно подтверждённое владельцем.

## Контракт

- Только рабочая база: `delay_reason_policy=all|primary`, по умолчанию `all`.
- `all`: одна работа один раз в каждой указанной группе, даже при нескольких причинах одной группы.
- `primary`: одна работа по основной причине. Если её нельзя однозначно установить, зависимые значения неизвестны; единственная известная группа полного списка однозначна и без отдельной отметки основной.
- Не меняются первичные данные, факты, роли, схема БД и остальные графы отчёта.
- Выбранный режим возвращается сервером, отражается в пояснениях граф G:L раздела3 и в редакции расчёта. Генерируемая ссылка Excel сохраняет его. Подмена режима при старой редакции даёт409.
- Снимок журнала не содержит структурированных причин: опция скрыта, явный параметр для него отклоняется400, неизвестный/пустой/повторный параметр тоже400.
- Vue сбрасывает результат/скачивание/пояснения при изменении опции и игнорирует поздний ответ прежнего режима. На результате подписан серверный режим, не текущий ввод.
- Неизвестность не заменяется нулём. По умолчанию «По всем указанным причинам», с пояснением о нескольких учитываемых причинах одной работы.

## Проверка

Две группы причин, первая основная: `all` → G=1,I=1; `primary` → G=1,I=0. Без основной и при двух группах `primary` → G/I неизвестны. Остальные клетки и происхождение не меняются. API, пояснения, Excel, устаревшая редакция, Vue отмена и фактический браузер проверяются раздельно.
