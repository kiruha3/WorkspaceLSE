## Выбранный подход

Рассмотрены конфигурационный словарь (нет редактирования/истории), чтение плана из журнала (журнал не является надёжным источником плановых величин) и отдельный годовой реестр в PostgreSQL (выбран). Это самостоятельная часть существующего Django/Vue, не новый сервис. Оба источника отчёта используют один текущий план выбранного года; снимок регистраций остаётся неизменным, но план имеет собственную редакцию и участвует в проверке выгрузки. Чистая функция расчёта получает снимок плана явно, без скрытого DB-read или fallback294.

Standing режим владельца: автономное inline исполнение без повторных approval-петель, один свежий финальный reviewer. Технологии существующие; новые зависимости, worktree, push/merge, реальные роли/экспертизы и Google не меняются. После e00c486 сохраняется подтверждённый переключатель all|primary причин длительности, по умолчанию all, во всём расчёте и выгрузке.
