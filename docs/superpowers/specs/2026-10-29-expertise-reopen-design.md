# Возврат завершённой экспертизы в работу

Подтверждённый владельцем вариант: отдельная команда и настраиваемое право в ролях, без согласования руководителем. Только состояние `completed`; решение «без исполнения» не переоткрывается этой командой.

- Право `expertise.reopen`, стандартные области own/departments/institution; просмотр работы также обязателен. Setup получает только новое право по учреждению в персональную роль, по явному согласию владельца.
- POST `/api/v1/expertises/{id}/reopen/`: `expected_version`, непустая `reason`, заголовок `Idempotency-Key`. Блокировка материал → поступление → работа; повтор той же команды не создаёт второе событие.
- Выданные материалы (в том числе историческая выдача любой работы материала) исключены. Старый проверенный комплект выдачи после возврата не действителен.
- Событие WorkReopening хранит автора, время, причину, ссылку на прежнее закрытие и прежние исторические даты. Документы, номера, исполнители, редакции результата и закрытия не удаляются.
- Новое состояние in_progress; при существующей незакрытой приостановке — suspended, без выдуманной даты возобновления.
- Исторические текущие даты окончания снимаются, источник остаётся неизменным. Историческая работа не активируется автоматически: подтверждение основания и новое назначение остаются отдельными действиями. Импорт не перезаписывает работу после локального возврата.
- Прежнее закрытие не является текущим у открытой работы. Новый расчёт 15.1 и экспорт журнала не показывают отменённое окончание. Повторное завершение создаёт следующий номер закрытия.
- Карточка: раздел «Результат», кнопка «Вернуть в работу», форма причины и явное подтверждение; история возвратов доступна независимо от права действия. При сетевой неопределённости повторяется та же команда, при конфликте требуется обновить версию.
- Не менять реальные экспертизы для проверки. Миграция только добавляет таблицу событий; никакого удаления БД, массовой активации, новых зависимостей или push.
