# Производство: приостановки и сроки

Продолжение утверждённой общей спецификации §5.3 и §8, не новая архитектура. Владелец поручил продолжать реализацию без повторных согласований уже описанного пути. Django/PostgreSQL, Vue и существующая ролевaя политика сохраняются; старые проекты/журнал не меняются, push нет.

## Подход

Выбран встроенный блок производства в существующей карточке с формой действия и журналом фактов. Отдельный самостоятельный журнал заставлял бы искать контекст работы; общий PATCH состояния терял бы проверку перехода/историю. Микросервис и отдельный worker для этих коротких команд не нужны.

Эксперт своей работы, руководитель при совмещении экспертной роли и назначения, делопроизводитель с соответствующим правом выполняют команды по существующим `expertise.suspend`, `.resume`, `.deadline.record`. Должность сама по себе не разрешает действия. Чужой номер того же материала/комплекса не меняется.

## Факты и даты

- Приостановить можно `in_progress`, возобновить — `suspended`. Один открытый интервал на работу. Предыдущие интервалы, основания, кто/когда зарегистрировал обе границы сохраняются.
- Моя техническая трактовка дат событий: фактическая дата не раньше поступления, не позже сегодняшнего дня учреждения; интервалы не пересекаются, возобновление не раньше приостановки. Допускается внесение прошлого факта с явной причиной. Дата назначения не подменяет дату поступления.
- Поступление/завершение/выдача остаются разными фактами. Эти команды не завершают работу и не выдают материалы.
- Моя трактовка наглядного счётчика: календарные дни от поступления до даты расчёта включительно; пауза `[дата приостановки, дата возобновления)`, открытая пауза включает дату расчёта. В день возобновления производство активно. Это не правовой/рабочий календарь; метод показан в UI. Для закрытой работы без известного окончания показатель неизвестен, а не рассчитан до сегодня.
- Исходный срок, запрос нового срока и подтверждённое согласование — самостоятельные записи. Запрос не меняет действующий срок. Исходный срок можно явно уточнить новым событием с причиной; прежнее событие не стирается.
- Согласование требует документа с заявленным бумажным оригиналом или сохранённой копией. Новые виды `deadline_agreement` и `deadline_request` дополняют существующие постановление/определение; документ запроса не является подтверждением согласования. Постановление/определение тоже может подтверждать новый срок. Эти виды нельзя использовать вместо минимального основания приёмки.
- Неизвестный исходный срок остаётся неизвестным даже при известном согласованном новом сроке. Дата фиксирования согласования и срок исполнения не смешиваются; срок может быть будущим.
- Последние события определяются по фактической дате и времени регистрации при равенстве. Запись поздно полученного старого согласования не вытесняет более позднее согласование. Запросы не объявляются автоматически снятыми с контроля: полноценный контроль относится к следующей переписке.

## Технический договор

Каждая команда: expected_version, причина, Idempotency-Key. Блокировка работы, проверка текущей области/состояния/дат, факт+версия+аудит в транзакции. Повтор возвращает тот же ID события; permission-sensitive карточка читается свежей, не из старого кэша.

`POST /expertises/{id}/suspend/`: `{expected_version,suspended_on,reason}`; `/resume/`: `{expected_version,resumed_on,reason}`; `/deadline-events/`: `{expected_version,kind:initial|request|agreement,recorded_on,due_on,reason,document_id?:UUID|null}`. Ответ `{event:{id},expertise:ExpertiseDTO}`. Детали и списки получают `production`, `suspensions`, `deadline_events`. Полные документы редактируются/скачиваются по собственным правам; скрытое основание возвращается restricted.

Реестр получает состояние и диапазон **календарных** дней; отфильтрованная область до пагинации. Фильтрация активных/рабочих дней и полный экспорт остаются последующими задачами, не выдаются за реализованные.

## Проверка и границы

Проверить конкурентные команды и повтор после утраты ответа; текущего/бывшего исполнителя; начальника-эксперта без обхода квалификации при назначении; смешанные области и соседнюю комплексную работу; две паузы, открытый интервал, одинаковые дни, запрещённые будущие даты; запрос без изменения срока; документ согласования и его видимость после отзыва прав; поздний старый факт; 409 с сохранением формы во Vue.

Результаты/СНДЗ/Q-R-S-T, завершение, переписка, выдача, импорт реального журнала, справочники причин и 15.1 — обязательные дальнейшие этапы общей цели. Их отсутствие не маскируется фиктивными кнопками.
