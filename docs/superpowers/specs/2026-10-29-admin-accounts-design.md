# Создание сотрудника и административный сброс пароля

Подтверждено владельцем 29.10.2026: оставить существующую выдачу логина и первоначального пароля; добавить создание нового сотрудника из раздела учётных записей и сброс пароля существующей учётки. Публичная регистрация не нужна.

## Решение

- В `/access` добавить «Добавить сотрудника» по существующему праву `employees.create`. Первый шаг создаёт только ФИО через существующий `POST /employees/`, затем открывает обычные формы логина/пароля и назначения ролей. Ошибка создания логина не требует повторного создания человека. Для уже имеющегося сотрудника используется его карточка, без дубля.
- В `/people` оставить существующую форму, но показывать кнопку добавления также из карточки сотрудника. Несохранённые изменения защищены подтверждением; выполняющаяся команда не прерывается навигацией внутри страницы.
- Сброс — отдельное право `users.reset_password` в редакторе ролей, область `institution`. `POST /employees/{id}/account/reset-password/` принимает новый `password` и необязательное `reason`; проверяет стандартные правила Django, меняет только хеш пароля и записывает факт в аудит. Логин, активность, должности, специальности и роли не меняются. Старые сессии перестают проходить стандартную проверку хеша Django при следующем запросе.
- В существующей форме персонального входа добавить «Сбросить пароль», два ввода нового пароля и подтверждение команды. Пароль не возвращается API, не хранится в истории/браузерном хранилище и очищается после успеха/закрытия формы. Сброс не является письмом или ссылкой через email и не вводит обязательную смену при входе.

## Рассмотренные подходы

1. Только создание логина у импортированного сотрудника: уже реализовано и не решает добавление нового человека.
2. Явное создание карточки → существующая форма учётки → существующее назначение ролей: выбранный владельцем путь; минимальные изменения без нового механизма регистрации.
3. Публичная регистрация/приглашения по email: не нужны в текущем объёме.

## Ограничения и проверка

Схема БД не меняется. Рабочие пользователи, пароли и роли не меняются для демонстрации. Новое право не выдаётся существующим ролям автоматически; отдельный запрос владельцу касается только персональной роли setup. Соседние несохранённые изменения сворачивания напоминаний сохраняются.

Тесты: реальное хеширование/смена пароля и запрет старого входа, запрет команды без права/после отзыва, отсутствие пароля в ответе и аудите, отсутствие автодоступа/реактивации; интерфейс обоих путей создания и сброса, неверное повторение пароля, ошибки сервера и сохранение введённых данных/защита от повторной команды.
