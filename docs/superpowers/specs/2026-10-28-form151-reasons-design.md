# Причины из принятого результата в форме15.1

Продолжаем цель полного рабочего пути без повторных согласований уже порученной реализации. Текущий код умеет сохранить структурированные причины результата/возврата, но registry-калькулятор их не использует. Этап закрывает этот разрыв, не выдумывает причины старых работ и не меняет Google/PHP.

Подходы: разбирать свободный текст старого журнала — неоднозначно, отвергнуто; сделать второй калькулятор — дублирование; подключить принятые структурированные факты к существующему — выбран исполнителем. Выбор основан на текущих справочниках и заголовках сохранённого официального бланка, не вводит новую правовую классификацию.

## Контракт

- Только registry. Старый journal-preview, его клетки и правила не меняются. Версия registry становитсяv2, fingerprint включает версию расчёта и все использованные принятые причины/распределения.
- Раздел1 G/H/I: outside_expert_knowledge / materials_insufficient_addition_refused / science_cannot_answer. Считаются полные СНДЗ, по одной причине на принятую работу. Неизвестная/новая несопоставленная причина даёт пустоты всех трёх граф с адресной диагностикой, не «иное» и не ноль.
- Раздел2 I/J/K/L: methods_insufficient / materials_insufficient / objects_uninformative / other. Суммируются количества нерешённых вопросов только принятого заключения/акта. Полный СНДЗ не распределяется по причинам вопросов автоматически. T=0 и пустое распределение означают известные нули. T>0 требует allocations_complete=True, уникальных известных причин, положительных целых количеств и суммы=T. Неизвестный/противоречивый T, неполное/несопоставленное распределение дают пустоты с диагностикой; не распределять T догадкой.
- Раздел4 P/Q/R/S/T: no_technical_facilities / no_required_specialist / no_special_conditions / appointing_party_request / other. Только принятое решение without_execution в периоде. Неизвестная причина не становится «иное». Неизвестная дата решения остаётся неизвестной даже при дате выдачи.
- Используются последнее WorkClosure и его ResultRevision/UnresolvedAllocation в одном согласованном SQL SELECT. Новейший черновик, чужие распределения и прежнее подтверждение не подменяют принятые сведения. Неактивная причина в уже принятом результате учитывается по семантическому коду, не названию; новый код требует явного сопоставления.
- Исторические строки без принятого результата не получают выдуманных структурированных причин из raw/facts/описи. Причинные пробелы указывают конкретные UUID и ссылки на карточки. Все прежние суммы и правила неизвестных сохраняются. Ведомственный итог не удваивается из-за родительских строк специальностей.
- Веб показывает новые графы только для registry и позволяет раскрыть происхождение значения/пустоты. Предупреждение различает уже рассчитываемые причины от пока отсутствующих причин сроков/повторности/3214-р. Экспорт пишет те же числовые/пустые клетки в исходный бланк.
- Никаких бизнес-записей, прав, аккаунтов, миграций, пакетов, дополнительных серверов, push/merge/worktree. Веткаimplementation. Реальные472 работы не меняются; новая выгрузка — отдельный файл. Отчёт остаётся предварительным, полная цель — активной.

Проверка: литеральные контрольные примеры всех12 причинных граф, неизвестные/несопоставленные/неполные случаи, одновременное принятие и черновик, исправление принятого результата и устаревшая выгрузка409, один SELECT, отсутствие записей. Компонентные проверки registry/journal/trace. Полные тесты и сборка, один свежий review, реальный браузер/download и804 клетки официального Excel.
