# Характер назначения и предыдущие заключения

Продолжение цели полного рабочего процесса и15.1 послеd24b84b (677backend/270frontend). appointment_nature уже существует, но после регистрации не редактируется обычной карточкой, а H:N раздела4 не рассчитываются. Данные источника не подтверждают первичность по умолчанию. Владелец разрешил эксперту уточнять характер назначения, независимо от комиссии/комплекса. Неизвестное нельзя заменить primary.

## Подход

Варианты: отдельный отчётный JSON проще, но лишает документы FK/проверяемых связей; расширение ResultRevision смешивает характер назначения с принятым заключением. Выбран отдельный WorkClassification OneToOne к Expertise, PreviousConclusion OneToMany к профилю и неизменяемые ClassificationRevision. appointment_nature остаётся существующим полем Expertise; комиссия/комплекс, номер, люди, отдел, результат и выдача не меняются этой командой. Общие механизмы версий/блокировок/FactHistory/useCommandAttempt переиспользуются. Django/PostgreSQL/Vue, без пакетов/новых серверов.

## Карточка

Раздел «Характер назначения и предыдущие заключения» виден постоянно. Редактор выбирает nature, добавляет/убирает предыдущие заключения и отдельно подтверждает полноту списка. Все три логические оценки (неизвестно/да/нет) видимы; «не подтвердилось» не выводится из СНДЗ или текста. Существующий документ поID с серверной проверкой, либо новая загрузка через BasisDocumentForm с теми же правами. Документ доступен только через разрешённую точную связь; это не открывает все файлы материала. История показывает человекочитаемые сведения и ссылки-ID, не одинаковые before/after при изменении только доказательства. Черновик сохраняется при403/409, версия принимается явно, неопределённая попытка фиксирует path/body/key и вложенные документы, поздний ответ игнорируется после смены карточки, dirty-guard действует.

## Расчёт

Registry-v5 одним SELECT получает nature/наличие профиля/полноту и ArraySubquery предыдущих заключений. Без профиля полнота неизвестна, не первичность. H раздела4: законченная повторная судебная экспертиза. I/J: после ФБУ СЭУ Минюста/из них не подтвердившая выводы по тем же данным; K/L: иные государственные; M/N: иные организации/частные эксперты. Одна работа считается один раз в каждой подходящей группе; несколько прошлых заключений одной группы не умножают счётчик. Полный список с неизвестной группой не делает отсутствующие группы нулями. Неполный список может доказать положительный признак, но не отрицательный. Для J/L/N нужны same_input_data=True и confirms_previous=False; иначе неизвестные факты не становятся «не подтвердилось». Primary/additional даёт0 в этих repeat-графах. Неизвестный nature даёт адресный пробел, а не0.

Для ordinary conclusion правило определено. Вопрос о включении полного СНДЗ задан владельцу и пока не решён: у законченного СНДЗ, который повторный или неизвестного характера, repeat-графы остаются неизвестными с отдельной диагностикой; положительный/отрицательный ответ владельца будет явным versioned изменением. Это не ложный ноль и не догадка о правиле.

Проверка заполненного примера по поручению владельца (28.10.2026): `C:/Users/kirill/Downloads/10004_151_2609.xlsx`, раздел4 H58:N58 и H107:N107 = [1,0,0,1,0,0,0]. Единственная повторная — строительно-техническая16.1, после иного государственного учреждения. В разделе1 F65=F108=4: все четыре полных СНДЗ — автотовароведческие18.1. В разделе4 H64:N64 по этому виду стоят семь явных нулей. Формул в этих клетках нет: это готовые значения без поэкспертной расшифровки. Образец не содержит подтверждённого пересечения «повторная + полный СНДЗ», поэтому не доказывает ни включение, ни исключение такого случая. За6месяцев в образце2606 также одна повторная16.1 и три СНДЗ; это не снимает неоднозначность. Не объявлять предположение «только заключения» подтверждённым владельцем. Подсказка должна прямо отделять проверенный обычный случай от пока не установленной политики полного СНДЗ.

## Приёмка и ограничения

Дополнение владельца: смысл и алгоритм каждой графы должны быть расписаны в интерфейсе. Backend возвращает versioned column_rules для всех действительно рассчитываемых граф6разделов: номер графы бланка, смысл, единица, источник полей, дата отбора, неизвестность и ограничения. Подсказка в заголовке открывает объяснение; трассировка клеток сохраняется отдельно. Для journal правила отдельно поясняют чтение снимка/исторические нули и не обещают registry-поля. Правила входят в fingerprint; их нельзя заменить клиентским предположением при старом/неполном API. Не рассчитываемые графы сроков/7–8 остаются явно не реализованными, а не получают фиктивное объяснение работающего расчёта. Предыдущее816сохраняется, инструкции не меняют саму формулу.
