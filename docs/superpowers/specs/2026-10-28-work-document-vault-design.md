# Архив документов экспертизы

## Цель и исходное состояние

После среза выдачи201e478 следующий обязательный пробел общего процесса — единый доступный архив файлов работы и явные дополнительные связи. Сейчас Document/FileVersion существуют, но произвольной связи документа с экспертизой и общего списка нет. Общий файл в двух работах, снятие одной связи без удаления другой — требованиеAC14. Владелец также просил URL и загрузку из папки с просмотром внутри веба.

Решения владельца о полном СНДЗ/возврате/комиссии ещё ожидаются; они не мешают этому независимому модулю. Полная цель не сужается до архива: после него остаются офисное производное представление, управляемые серверные папки, документы supplements/replaces, все ролевые E2E, production-профиль и фактические пробелы официального15.1.

Продолжается выбранное владельцем автономное inline исполнение без повторных approval-петель. Django/PostgreSQL/Vue и существующее хранение сохраняются. БезPHP/Googlewrites/push/merge/newworktree, без массовых связей/реальных файлов/новых grants. Outputs/ и запрещённое к удалению .superpowers сохраняются.

## Подходы и выбор исполнителя

Копирование файла на каждый номер нарушает общий файл/историю. Ещё один длинный блок всех форм внутри карточки делает её менее понятной. Выбраны одна сущность Document с FileVersion, явные дополнительные связи к работам и отдельная страница архива из карточки. Это решение исполнителя в рамках утверждённой архитектуры, не новая бизнес-политика владельца.

В этом модуле работают загружаемая копия, бумажный оригинал и явно зарегистрированная внешняя URL-ссылка, а локальная папка — разовая выбранная пользователем пакетная загрузка. Сервер сам не обходит диски/сети и не скачивает URL. Постоянные подключённые папки требуют отдельных настроек источников. URL может не разрешать встраивание; всегда есть явное открытие источника. Для приёмки/подтверждённых событий URL без сохранённой копии не считается файлом или бумажным оригиналом.

## Данные и права

- `WorkDocumentLink`: UUID, expertise FK(PROTECT,related_name=document_links), document FK(PROTECT,related_name=work_links), note, actor(User), created_at, detached_at nullable, detached_by nullableUser, detach_reason. Активная пара expertise/document уникальна. Снятие связи — сохранённый факт, не удаление файла/Document/старой связи; повторное прикрепление создаёт новую связь.
- `Document.kind` дополнен `case_material`; `source_kind` дополнен `external_link`; source_url Char2048 blank. Дляexternal_link URL обязателен, для остальных пуст. HTTP/HTTPS, без username/password в URL, без автозапроса источнику. БД ограничивает согласованность типа/пустоты; сервис/serializer — формат.
- `FileVersion.relative_path` Char1000 blank — только относительный путь выбранного браузером файла, не серверный путь. Нормализуется `\\`→`/`, запрещены абсолютный/drive/.., controlchars и несовпадение basename. Путь не используется для хранения: storage UUID-путь остаётся прежним. Включается в idempotency payload только при непустом значении, чтобы прежние успешные ключи оставались совместимыми.
- Новые независимые права `documents.link`/`documents.unlink`, own/departments/institution; без автоматической выдачи. Обязательны expertise.view и documents.view. Own по текущему исполнителю/историческому текущему участнику; для native — также зарегистрировавший работу делопроизводитель. Автор массового исторического импорта не становится владельцем всех работ. Изменение бинарного файла по-прежнему требует существующее documents.upload на Document, связь не даёт upload authority.
- Команды блокируют material→receipt→work; проверяют нынешние права/Documentview перед receipt replay, expected_version работы, idempotency. При успехе version+1 и аудит. Дополнительная связь не меняет основание поступления, принятый итог/счёт/выдачу; допускается и после завершения/выдачи как отдельное архивное сведение, не исправление принятого события.

## API и единый список

GET `/expertises/{id}/documents/`: пагинированный архив с контекстом работы `{id,registration_number,version,state,material,department}`, can_link/can_unlink/can_create, видами документов и results. Фильтры search/kind/page; поиск не проверяет закрытые пользователю названия. Одна строка на Document; origins содержат только доступные контексты этой работы, не чужие номера.

Источники агрегируются без новых записей: основание поступления; сроки; редакции результата/причины вопросов/принятые окончания;3214-р; предыдущие заключения; доказательства причин сроков; доступная текущая переписка этой работы (и письма материала только при наличии права видеть такой контекст); документы комплекта этой работы и доступное подтверждение выдачи; активные WorkDocumentLink. Опись и исходный текст не превращаются в загруженный файл. Неактивные дополнительные связи доступны отдельной историей с редактированием/preview запрещёнными, если доступ к Document после снятия потерян.

Origin с принятым файлом имеет явный `accepted_version_id`, включаяnull; UI не подставляет latest вместо принятого. Общий просмотр можно переключить явно с предупреждением. Структурную связь (основание/окончание/письмо/комплект) нельзя снять этим API: она управляется соответствующим процессом. Дополнительную снимает только documents.unlink.

POST `/expertises/{id}/documents/`: `{expected_version,document_id,note?,reason}` → `{event:{id},library:...}`. Существующая активная связь с новым ключом409, повтор прежнего ключа возвращает событие, не активирует снятую связь. POST `/expertises/{id}/documents/{link_id}/detach/`: `{expected_version,reason}`; чужая связь404, stale409, нет права403, без частичных записей. GET `/expertises/{id}/documents/options/`: поиск доступного существующего Document для прикрепления, требует правоdocuments.link именно в этой работе. Create/upload используют прежние endpoints с расширенными источниками.

Новая ссылка даёт чтение файла только через текущую разрешённую работу и documents.view. Снятие одной связи не снимает другую, но не даёт бывшему пользователю бессрочный обход через историю. Создание связи не раскрывает другие связанные работы и не расширяет право загрузки новой версии.

## Экран и загрузка

Отдельный маршрут `/expertises/:id/documents`, ссылка из карточки при серверной capability `work_documents` и documents.view. Слева/сверху список с видом/происхождением/поиском, справа/ниже — выбранный документ, происхождение и версии/preview. Адаптивная раскладка. Есть загрузка нового документа, выбор существующего, пакет выбранных файлов/папки, история снятых связей. Отсутствие новых прав объясняется, не выдаётся автоматически.

Загрузка папки не читает её без выбора оператора. До отправки видны все выбранные относительные пути, виды/названия и количество, предел100файлов. По умолчанию case_material, без распознавания бизнес-фактов. Загрузка последовательная, прогресс по файлам, подтверждённые успешные строки не повторяются. После ошибки выбранные файлы, DocumentID, upload/link keys и ввод сохраняются; можно повторить неуспешное. Частичный успех обозначается явно, не объявляется атомарной загрузкой всей папки. Новый GET не переписывает ввод/захваченный packet;409 требует явного принятия текущей версии.

Внешняя ссылка не загружается автоматически при открытии карточки/метаданных: отдельная кнопка просмотра, sandbox без scripts и referrer, явный исходный URL с noopener/noreferrer; возможно отдельное открытие при запрете встраивания. Можно подкрепить сохранённую копию обычной FileVersion, сохранив URL как происхождение. Неподдерживаемый офисный оригинал скачивается с честным сообщением; конвертация не объявляется реализованной.
