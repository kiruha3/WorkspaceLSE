# Soft Completion and Per-Expertise Reminders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Разрешить завершение с неполным цифровым комплектом и показывать вычисляемый список незаполненного по каждой доступной экспертизе в личном кабинете.

**Architecture:** Сохраняем существующие команды завершения/выдачи и разделяем блокирующие ошибки и предупреждения. Напоминания — read-only проекция текущих фактов, а не новая модель. Единственная предполагаемая миграция делает существующий `WorkClosure.document` nullable; она требует подтверждения технического уточнения в спецификации.

**Tech Stack:** Django 5.2, PostgreSQL 17, DRF, Vue 3, TypeScript, pytest, Vitest; без новых зависимостей.

**Spec:** `docs/superpowers/specs/2026-10-29-soft-completion-reminders-design.md`.

## Global Constraints

- Нет новой таблицы/модели/полей уведомлений, фоновой рассылки или автоматического исправления рабочих данных.
- Неполнота цифрового комплекта — предупреждение для всех видов работ; права, версии, достоверные даты/состояния и математическая корректность введённых чисел не отключаются.
- Пустое не равно нулю; бумажное наличие не выводится из отсутствия цифрового файла.
- Рабочие экспертизы и Google не изменяются для тестирования; миграция рабочей БД только после резервной копии.
- Исторические принятые версии не подменяются поздней загрузкой. Новые чужие сведения через напоминания не раскрываются.
- Постановление/определение и итог экспертизы остаются ожидаемыми документами, но цифровая неполнота не запрещает завершение. Текущая приёмка с основанием не ослабляется автоматически.
- Бинарные файлы остаются на файловой системе; в БД — ссылки/пути, реквизиты и предусмотренный моделью текст. Не добавлять BLOB-хранение. Подключение постоянной внешней папки и новое поле полного текста — следующий документный этап, а не часть уведомлений.

## Review Focus

- Завершение с `document=null` не создаёт вымышленную запись Document и не ломает архив, отчёт или выгрузку.
- Поздний файл убирает текущую документную недостачу, не переписывая принятую версию прежнего события.
- Нулевые счётчики и неприменимые причины не создают ложных напоминаний.
- Смена/отзыв роли не раскрывает чужие номера, подписи документов или прежний ответ другого пользователя.
- Число запросов не растёт пропорционально числу строк; пагинация не теряет незаполненные работы и не повторяет их.

## Task 1: Мягкое завершение без обязательного документа

**Files:** `backend/apps/expertises/{models.py,results.py,result_serializers.py}`, новая миграция после `0012_optional_construction_evidence`, связанные потребители nullable closure.document; `frontend/src/modules/expertises/ResultPanel.vue` и API-типы.

**Interfaces:** Существующие `complete_work`, `return_work`, `correct_closed_work` сохраняют ключи, версии и права. `result_readiness` возвращает отсутствие файла как отдельные документные предупреждения, а не `completion_blockers`. `ClosureOutput.document` допускает `null`.

- [ ] Написать failing tests для завершения заключения/акта/СНДЗ и возврата без документа и с документом без версий; проверить отсутствие фиктивных документов, сохранение даты/результата и `accepted_version=null`.
- [ ] Запустить новые тесты и увидеть ожидаемые отказы прежних проверок.
- [ ] Сделать существующий FK nullable, обновить serializers и безопасную обработку `None` во всех читателях closures; убрать обязательность файла, но оставить проверку вида фактически выбранного документа, дат, ролей и версии.
- [ ] Адаптировать клиентскую валидацию/подсказки; тестом проверить доступное завершение без файла и видимое предупреждение. Не менять арифметические проверки статистики.
- [ ] Проверить реальные команды, повтор ключа, конфликт версии, запрещённую роль, неверную дату, файл неверного вида и существующий путь с принятыми байтами. Прогнать профильные backend/frontend tests и commit.

## Task 2: Мягкая проверка выдачи

Подтверждение выдачи остаётся отдельной командой с фактическими реквизитами.

- [ ] Написать failing tests по заключению, исследованию, СНДЗ, возврату и комиссии с неполным комплектом: предупреждение есть, check/confirm допустимы при корректных прочих фактах.
- [ ] Воспроизвести RED, разделить состояния и документную полноту; не объявлять неопределённую комиссионную привязку подписок установленной.
- [ ] Обновить UI на отдельные блоки «Нужно заполнить» и действительных запретов; показать, что недостающие документы не запрещают действие.
- [ ] Проверить обратную совместимость сериализации, аудит/идемпотентность, поздний файл без подмены check snapshot, запрет повторной выдачи и незаконченных работ. Прогнать профильные тесты и commit.

## Task 3: Список незаполненного по каждой экспертизе

**Files:** новые `backend/apps/expertises/completeness.py`, `completeness_api.py`, `backend/tests/test_expertise_completeness.py`; `backend/apps/expertises/urls.py`; новый `frontend/src/modules/expertises/IncompleteExpertises.vue` с тестом; `frontend/src/modules/HomePage.vue` и API-типы.

**Interfaces:** `GET /api/v1/expertises/incomplete/` — стандартная страница `{count,next,previous,results}`. Каждый элемент `{id,registration_number,state,missing:[{code,message}]}`; группировка строго по Expertise, проверка через существующий `expertise_scope_queryset(...,'expertise.view')`. Клиент строит ссылку `/expertises/<id>` из UUID, не из внешнего URL.

- [ ] Добавить failing API tests: несколько недостач одной работы остаются в одной группе, полная работа исчезает, текущие/исторические записи поддержаны, нули не считаются пустыми.
- [ ] Отдельно проверить ожидаемые основание и итог: отсутствие внесённого источника видно по этой работе, наличие принятого источника не ошибочно называется отсутствием бумажного документа. HTTP-ссылка, загруженный файл и планируемый папочный источник не приравниваются друг к другу без поддержки соответствующего адаптера.
- [ ] Воспроизвести RED и реализовать вычисление из существующих источников результата/документов/комплекта и прежних report_gaps. Никаких записей при GET и новых моделей.
- [ ] Проверить области свои/отделы/учреждение, отзыв роли, недоступные документы без раскрытия названий; ограничить выдачу пагинацией и исключить N+1.
- [ ] Добавить failing UI tests, затем блок «Не заполнено» на HomePage: номер, список недостач, ссылка; загрузка, ошибка с повтором, пустой результат и отсутствие запроса без expertise.view. Никакого фонового polling.
- [ ] Прогнать полный backend/frontend, TypeScript/build, Django check, makemigrations --check --dry-run, git diff --check. Независимое ревью и один исправляющий проход по найденным существенным замечаниям.
- [ ] После подтверждения плана создать резервную копию перед миграцией; не менять бизнес-записи при проверке GET. Перезапустить только существующий Django, переиспользовать Vite. Проверить рабочий список read-only, обновить документацию и сообщить результат. Автоматический push новых изменений не подразумевается.
