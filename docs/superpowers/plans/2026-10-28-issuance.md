# Подготовка и выдача материалов Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Довести завершённую экспертизу до проверенного комплекта и фактической полной выдачи с независимыми датами и неизменяемыми файлами.

**Architecture:** issuance Django-модуль с редакциями/проверками/фактом выдачи; Material-first сериализация с регистрацией/окончанием; Vue журнал/карточка и краткий статус в экспертизе. Общие execute_once/documents/audit/scopes, не новая почтовая система.

**Tech Stack:** Текущие Python3.13/Django5.2/PostgreSQL17/Vue3/TS/Vite, без новых зависимостей или серверов.

**Spec:** `docs/superpowers/specs/2026-10-28-issuance-design.md`, общаяspec§5.4/access§6. Начало с `cfd2b2e`.

## Global Constraints

- ais-lse/implementation, без push/merge/worktree и старыхPHP/VM/Excel/Google. Реальные роли не расширять, учебные только explicitopt-in.
- Частичная выдача не утверждена. Все работы материала закрыты, комплект подтверждён; неизвестные политики4/6/СНДЗ/возврат/комиссия блокируют соответствующий вариант до ответа владельца.
- Выписанный счёт не означает оплату; отправка письма, окончание экспертизы и выдача — разные факты. Принимается WorkClosure.accepted_version, не произвольныйlatest.
- Mutation reason/key/version, минимальныйreceipt/freshprojection. Material→Receipt→Expertise→Package→Documents→refs. Новое issue не рекламировать до всех команд.
- Один backend pytest, один Vite0.0.0.0:5173/backend8000/PG55432. Свой scratch, старые сохранённые каталоги не читать/удалять. Общая цель активна до импорта/15.1/полного документооборота.

## Review Focus

- Между check иissue зарегистрирована ещё работа/изменён итог — выдача не проходит со старым снимком и не противоречит физическому составу.
- Материал пересекает отделы/назначения, есть широкое чтение и узкое действие — один видимый номер не выдаёт весь материал и не раскрывает скрытыеwork/counts.
- Новый файл/отзывdocuments.view послеcheck или потерянногоответа — старый ключ не возвращает чужиеbytes, принятый итог не заменяется позднимсканом.
- Два ключа/двеодновременныевыдачи/issue↔registration/issue↔correction — один факт, без deadlock/частичногоаудита/нового номера на уже выданном материале.
- Refresh открытой формы до первой отправки/загрузка файла с потерей ответа — не перебазирует старые поля, не создаёт дубликат документа/версии/выдачи.
