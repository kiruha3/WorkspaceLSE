# Пакетная регистрация комплексной экспертизы

> Исполнение: superpowers:executing-plans, текущая ветка стенда. Пользователь утвердил несколько номеров без ручного создания объединений.

**Цель:** регистрировать 2 и более номеров по разным специальностям одной операцией, показывать их связь и прикреплять общий файл без копирования.

**Архитектура:** существующие Receipt → Material → ComplexGroup → Expertise и WorkDocumentLink. Изменения API/форм, без изменения моделей и миграций. Обычная регистрация сохраняет контракт. Общий характер назначения и комиссионность применяются ко всем строкам; номер, отдел, специальность, исторический номер и 3214-р задаются по строкам.

**Стек:** Django/DRF, PostgreSQL, Vue 3/TypeScript.

**Спецификация:** согласованный в чате сценарий; текущий контракт `docs/api-intake-registration.md` дополняется по результату.

## Ограничения и проверки

- Номер вводится вручную; подсказка общей последовательности не резервирует номер.
- Права регистрации проверяются для каждого отдела, чтение связанных номеров ограничено прежними правами.
- Ошибка любой строки откатывает весь пакет, включая объединение и события.
- Повтор с тем же ключом восстанавливает пакет; другой payload конфликтует.
- Специальности и порядковые номера внутри пакета не повторяются; год и категория едины.
- Общий документ связывается только явным действием, с проверкой прав на каждый номер; файл и завершение работ не дублируются автоматически.

## Результат проверки

- Сервер: 60 тестов регистрации, конкуренции и архива документов прошли на отдельной test-БД.
- Фронтенд: 501 тест прошёл; после исправления типизации теста карточки повторно прошли её 7 тестов и TypeScript/Vite build.
- `manage.py makemigrations --check --dry-run`: No changes detected; `manage.py check`: без замечаний.
- Независимое ревью нашло включение чужих номеров в автоматическое название комплекса. Находка воспроизведена тестом RED и исправлена нейтральным названием; повторный серверный прогон GREEN.
- На стенде проверена форма двух номеров без отправки примера в рабочую БД; снимок `.runtime/complex-batch-registration.png`.
- Удалены только 6 безымянных объединений текущего поступления без связанных работ, под блокировкой материала. Снимок перед удалением: `.runtime/complex-groups-empty-backup-20261029.json`, изменения отражены в аудите.
- Решение: сохранить старый одиночный API и именованные группы для совместимости, новая форма их не вызывает. Пакет использует существующие права по каждому отделу.
- Решение: общий файл добавляется в архив явным флажком; результат и окончание каждого номера оформляются отдельно.
