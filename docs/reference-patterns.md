# Что используем из Doca и Docaml

27 октября 2026 года. Оба проекта в `E:/DD` изучены только для чтения по запросу владельца. Их исходники, настройки, репозитории и окружения не изменялись. Это выбор применимых архитектурных подходов, не аудит и не перенос всего продукта.

## Применяем

| Наблюдение и источник | Решение для АИС |
|---|---|
| Doca: `backend/doca/api/endpoints/roles.py`, `schemas/roles.py`, `services/roles.py` разделяют HTTP, DTO и транзакционные операции | В DRF сохраняем ту же границу: serializers/views, services и policies. Переходить на другой API-framework только ради сходства не требуется |
| Doca: `perms/roles.py`, role service, `tests/api/test_custom_roles.py` используют каталог действий, редактируемую роль и назначенных пользователей | Свои `Role`, `RolePermission`, `EmployeeRole`; полномочия по действиям и областям, без жёсткой проверки названий роли. Проверяем негативные сценарии так же, как успешный CRUD |
| Doca: `tests/api/test_permissions_api_v2_files.py` проверяет разные области доступа и отказы для файла | Одинаковые policy-фильтры для списка, карточки, файла, экспорта и агрегатов; отдельные проверки запрета стажёра и пересечения областей |
| Doca: `docs/features/1.8.8.2-audit-logging-workspaces-roles.md`, role service фиксируют изменения доступа | AuditEvent сохраняется в той же транзакции с изменением роли/назначения; история не зависит только от console.log браузера |
| Doca: `frontend/src/ui/README.md` описывает типизированные кнопки, чекбоксы, диалоги, уведомления и доступность | Небольшой собственный shared UI-kit Vue в палитре Абаканской ЛСЭ; loading/disabled, indeterminate, доступная ошибка и подтверждение несохранённой формы |
| Doca: `frontend/src/stores/role-edit.ts` хранит originalRole и изменённую форму | Редактор роли хранит исходную и текущую версии, показывает изменения, не подтверждает успех при ошибке API. Состояния чекбоксов вычисляет Vue, без querySelector/setTimeout для синхронизации DOM |
| Doca: `frontend/src/components/Base/Table/BaseTable.vue`, `useTableList.ts` выделяют повторяемые таблицы | Общий табличный компонент, устойчивый ключ UUID, единый договор фильтра/пагинации. Сервер сортирует весь разрешённый набор; агрегаты и выгрузка не ограничены текущими загруженными строками |
| Docaml: `backend/processing/pipeline/process.py` версионирует стадии преобразования; pipeline отделяет обработку документа от выдачи результата | Версия конвертера/предпросмотра и расчётных правил сохраняется с производным результатом. Оригинал не перезаписывается; статус и ошибка задания видны отдельно |
| Doca: `management/commands/jobs.py` предлагает управляемую команду создания/чтения задания | Если потребуются длительные операции, делаем наблюдаемые Job со статусом, результатом и повтором. Веб-запрос не изображает завершённую конвертацию до окончания worker |

## Не переносим автоматически

- Большую OCR/ML-платформу, брокер, распознавание, внешние облачные SDK и весь список зависимостей Docaml. Для 15.1 и учёта экспертиз они не нужны; распознавание постановлений можно добавить позже отдельным подтверждаемым помощником.
- Смешение старого и нового API, нескольких state-management систем, jQuery и Vue. В новой АИС один REST-контракт и Pinia для общего состояния.
- JWT/refresh tokens лишь потому, что они есть в Doca: для нашего браузерного приложения выбрана одна origin и Django session. Отдельные внешние клиенты — будущий договор.
- Приобретённые/проприетарные просмотрщики и незаявленные лицензии. Начинаем со стандартного просмотра PDF/изображений и своей модели файлов/версий.
- Локальную сортировку загруженных строк как сортировку всей таблицы. В просмотренном composable именно локальные rows сортируются в браузере; наш реестр требует серверного порядка.
- Возвращение ошибки из HTTP-клиента как будто это успешные данные. Наш клиент бросает типизированную ошибку; уведомление об успешном сохранении возникает только после подтверждённого ответа.
- Удаление используемой роли вместе с историей. В АИС роль и справочное значение деактивируются; прекращение конкретного назначения — отдельное событие.

Исходные файлы служат свидетельством рассмотренных вариантов. Новый код пишется под спецификацию АИС и её тесты, без зависимости от пакетов или локальных `.env` проектов Doca/Docaml.
