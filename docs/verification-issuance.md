# Проверка выдачи материалов

Общая цель остаётся незавершённой: полный рабочий путь, импорт и серверная форма 15.1 ещё требуют работы. Этап переписки принят отдельно на `cfd2b2e` с 244 серверными и 122 клиентскими тестами.

## Часть 1: подготовка комплекта

Первый тест до реализации падал с404 на чтении комплекта материала. После создания модуля прошли 22 проверки API: неполный черновик и история, ключи/версии/повторы, четыре известных категории, пять неутверждённых вариантов комплекта, бумажные оригиналы и загружаемые копии, недоступные документы, запрет удаления скрытых приложений, область всех работ материала и отдельная область записи, подбор документов, файловый доступ без права загрузки и сохранение отредактированного справочника.

При первой проверке моделей выявлено зарезервированное имя Django `check`: внутренние FK названы `package_check`, внешний контракт остаётся `check_id`. Это техническое уточнение, не изменение рабочего процесса.

Полный серверный прогон первой части: **266 из 266 за 352,09 с**, Django check без замечаний, расхождений моделей и миграций нет. Коммит `8c77aa1`. На момент первой части миграции работающей БД и перезапуск ещё не выполнялись, незавершённая выдача не объявлялась интерфейсом и `/me.supported_modules`.

## Принятые решения

- Продолжается существующий репозиторий и ветка `implementation`, без новой рабочей копии, push и merge. Исполнение здесь, одно итоговое независимое ревью всего среза; цена — обязательная общая проверка границ и браузерного пути.
- Уже выбранные Django/Vue не согласовываются заново. Владелец поручил продолжать; конкретные отсутствующие правила заданы отдельными неблокирующими вопросами. Если выбранное правило не подойдёт, оно корректируется до эксплуатационной приёмки.
- Пока поддерживается одна полная выдача материала, не неутверждённые частичные выдачи. Повторная выдача и исправление после неё потребуют отдельной процедуры.
- Неуточнённые комплекты 4/6, СНДЗ, возврата и комиссии явно блокируют готовность. Это не исключение их из общей цели; по ним ожидается подтверждение владельца.

## Часть 2: проверка и выдача

Перед реализацией 21 проверка команд, межролевого HTTP и учебного флага падала, 3 прежние проходили. Ещё 5 конкурентных сценариев падали на отсутствующей проверке комплекта. После реализации прошли 29 объединённых тестов, затем 49 расширенных проверок, включая реальные HTTP-сессии по категориям 1/2, гонки двух выдач, выдачи с регистрацией/корректировкой/новым файлом, старые успешные повторы, версии доказательства и область действия.

Дополнительно воспроизведена избыточная блокировка чтения файла собственной работы при ограниченном полном комплекте: ожидался200, был403. Исправлена именно файловая связь по общей спецификации: три права по видимой работе, без чтения чужого состава и без upload. Повторно прошли 27 проверок команд и файловых областей. Полный серверный прогон второй части: **296 из 296 за 437,43 с**, Django check без замечаний, дрейфа миграций нет; коммит `000b4c9`.

Независимая Vue-подзадача завершила реализацию в `frontend/`, не меняя backend/данные/серверы. Основной исполнитель повторил её полный прогон: **147 из 147**, TypeScript и production build без ошибок. Ограничение общего создания метаданных документа при полностью потерянном первом ответе записано явно, а не объявлено решённым проверками повторной загрузки файла.

## Часть 3: настоящий встроенный браузер

Новые миграции применены, исходные способы выдачи добавлены без сброса справочника. Только учебным ролям явно добавлены новые права через `workflow-demo --enable-issuance`. Перезапущен единственный Django; один Vite на `0.0.0.0:5173` сохранён. Пароли и данные подключения не публиковались.

Через обычные формы под `demo.clerk` подготовлен комплект ДЕМО `900001/3-1-26`: описание материалов, новая подписка с тестовым JPEG, бумажные сопроводительное и уведомление. Проверка закрепила редакцию 2, принятую версию 1 заключения при существующей более поздней версии 2 и версии приложений. Затем отдельно записана учебная выдача от 28.10.2026 нарочно с учебным получателем, основанием и бумажным подтверждением. Комплект `f738823c-1e6c-4069-a151-ca929c178110` получил состояние «Выдано», редактирование и повторная выдача исчезли. Это не реальная передача судебных материалов.

Отрицательный пример `900003/3-1-26` зарегистрирован через приёмку и оставлен незавершённым. Его комплект `262db812-5b23-4b44-be15-83ad49e2b34b` показывает «Работа ещё не завершена», проверка и выдача недоступны; окончание не выдумывалось. Под `demo.expert2` своя завершённая работа показывает дату выдачи и доступный комплект, но кнопок подготовки, проверки и выдачи нет. В журнале отбор «Выдано» за 28.10.2026 возвращает ровно положительный пример, не незавершённый.

Снимки находятся в игнорируемой `.runtime/`: `issuance-issued-browser.png`, `issuance-pending-blocked-browser.png`, `issuance-expert-readonly-browser.png`, `issuance-registry-browser.png`. ## Итоговое ревью и исправления

Один независимый ревьюер проверил `cfd2b2e..221bfbc`, не меняя файлы и не запуская серверы. Критических замечаний нет, существенных два; оба подтверждены собственными падающими тестами перед исправлением:

1. Потерянный ответ метаданных: повтор создавал другой Document, отсутствовал ключ UI; два одновременных запроса также давали разные ID. Теперь общий helper сохраняет ключ до первого запроса, сервер использует атомарный CommandReceipt с одним ID/аудитом, проверяет нынешние права и возвращает свежий документ с версиями. Устаревший API без заголовка оставлен совместимым и не получает обещания идемпотентности.
2. Основной состав выданной карточки открывал latest приложения вместо принятой версии. Два новых теста показывали V2 вместо V1 и поздний скан бумажного оригинала вместо отсутствующего подтверждения. Теперь основной блок выбирает снимок именно `issuance.check_id` по `item_id`, включая явный null; отсутствие снимка не подменяется latest. Явный просмотр другой версии сопровождается предупреждением.

После исправлений прошли 13 серверных проверок документов/одновременных повторов и 28 клиентских проверок общего helper и выдачи. Итоговый общий прогон на `3d04bee`: **302 серверных теста за 439,42 с, 150 клиентских тестов**, TypeScript и production build без ошибок, Django check без замечаний, изменений миграций нет, `git diff --check` чистый. Задача 3 закрыта проверяющим скриптом; второй контекст ревью не назначался. Ветка `implementation` остаётся локальной, без push и merge.

Исправление принятой версии дополнительно проверено настоящим IAB после перезапуска единственного Django. В только учебный выданный комплект добавлены поздняя V2 подписки и первый скан бумажного сопроводительного через штатный файловый сервис с ключами. Основной блок оставляет подписку на V1 и не открывает поздний бумажный скан автоматически. При явном выборе позднего скана показано «Просматриваемая версия не подтверждена этим событием». После перезагрузки снова выбраны принятые состояния. Снимок: `.runtime/issuance-pinned-after-late-scans.png`. Дата и факт выдачи не изменились.

Отложены три небольших замечания: формулировки недоступных действий после завершённой выдачи; вывод технического времени ISO вместо местного формата; дорогая сериализация всего разрешённого журнала при фильтрации состояния до пагинации. Последнее требует отдельного измерения на реалистичном объёме, эксплуатационная ёмкость не подтверждена.

## Полный журнал решений с ценой ошибки

Порядок соответствует решениям при выполнении плана и разборе единственного ревью.

1. Продолжена текущая `implementation`, без новой рабочей копии; backend выполнен здесь, одно итоговое независимое ревью. Цена: общая проверка должна ловить ошибки на стыках; push и merge не разрешены.
2. Уже выбранные стек и путь не отправлялись на повторное согласование после поручения продолжать. Цена: конкретные неподтверждённые правила владелец должен уточнить до эксплуатации.
3. Одна полная выдача материала, без неутверждённых частичных передач. Цена: повторная/частичная выдача требует отдельной процедуры.
4. Категории 4/6, полный СНДЗ, возврат и комплект комиссии не приравниваются молча к обычному заключению. Цена: эти варианты пока блокируются до ответа владельца.
5. Краткий статус выдачи работы отнесён к серверной части 2, а не к первому черновику модуля. Цена: он не был доступен на промежуточной первой части; теперь реализован и проверен.
6. Сохранение полной редакции требует чтения всех прежних приложений, чтобы скрытая проекция не удалила их. Цена: без такого доступа нельзя изменить даже примечание; нужен доступ или другой уполномоченный редактор.
7. Независимая Vue-часть выполнялась параллельно нативным помощником по фиксированному DTO, без собственных серверов/pytest. Цена: основной исполнитель должен самостоятельно проверить интеграцию; это не заявляется работой Kimi.
8. Отдельный файл читается по одной разрешённой связи с работой, даже если полный смешанный комплект закрыт. Цена: содержимое именно этого общего файла доступно по действующей связи; чужие работы, счётчики и upload не раскрываются.
9. Проверенный интерфейс закоммичен до итогового ревью; задача закрывается только после исправлений и общего прогона. Цена: промежуточный локальный коммит сам по себе ещё не принят и не должен отправляться наружу.
10. При разборе ревью повторно подтверждена блокировка неутверждённых комплектов. Цена: их готовность не объявляется частью принятого обычного сценария.
11. Повторная/частичная выдача и исправление после неё остаются отдельной незавершённой процедурой, обычные запреты сохраняются. Цена: корректировка после выдачи пока недоступна.
12. Ручная передача не означает автоматическую печать, выставление/оплату счёта или внешнюю доставку. Цена: эти операции пока выполняются отдельно, автоматизация не обещается.
13. Импорт и 15.1 не считаются выполненными вследствие приёмки выдачи. Цена: учебный пример не заменяет отчёт учреждения.
14. Папки, URL и конвертация офисных документов остаются следующим документным функционалом. Цена: сейчас доступны загруженные файлы, но не эти источники напрямую.
15. Количественная ёмкость журнала не подтверждена. Цена: при большой истории потребуется измерение и оптимизация до эксплуатации; дорогой фильтр отмечен как отложенное замечание.
16. Ключ создания метаданных поддержан без поломки прежних API-вызовов без заголовка, но всегда передаётся общим Vue-helper. Цена: старый вызывающий без ключа всё ещё может создать дубликат при своём повторе; новый UI и запросы с ключом защищены.
