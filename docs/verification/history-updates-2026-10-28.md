# Синхронизация исторического журнала —28.10.2026

Этап продолжает рабочий импорт472 регистраций и отчёт15.1 из БД. Исходные номера/исторические отделы сохраняются, нынешние отделы людей не подставляются. Google используется только для чтения; PHP не изменяется.

## Реализованный путь

`Источники журнала → новый снимок → сверка «Изменены» → проверка сопоставления → отдельный пакет обновлений → серверный протокол → текущая карточка/отчёт`.

Предпросмотр показывает типизированные отличия «было → станет», причины блокировки, версии работы/выбора и прежний источник. Прежнее сопоставление используется только как несохранённая заготовка; специальность берётся из новогоM, а при изменении текста исполнителя люди не выбираются молча.

`POST /api/v1/imports/<batch>/updates/` принимает reason и updates с row_id, expected_selection_version, expected_work_version, expected_source_row_id. Нужны существующие институциональные права чтения источника/применения. Права и аккаунты не создаются. Старое создание новых работ остаётся отдельной командой.

Пакет обновляет только неоперационную историческую работу. Нативные назначения, результаты, сроки, основание или комплект блокируют его. Ручное отличие текущих сведений от прежней подтверждённой базы тоже блокирует пакет: слияния по догадке нет. Историческая отметка выдачи допускает исправление метаданных отдельным пакетом с before/after; нативный комплект, даже черновик, не меняется.

Блокировки идут в общем порядке material→receipt→work→source, справочники блокируются целиком в стабильном порядке. Версии и источник перепроверяются после ожидания. Ошибка любой строки откатывает всё. Повтор ключа возвращает прежний протокол, изменённое тело409; отзыв прав проверяется и на повторе. При неопределённом ответе веб фиксирует пакет/ключ и блокирует редактирование до разрешения попытки.

`ImportApplication.links` сохраняет before/after, прежнюю строку, версию и action=updated; `ImportApplicationItem` связывает новый источник с тем же UUID работы и замораживает сопоставление. Исходные raw/facts/файлы не переписываются, прошлые приложения не удаляются. Новые окончания, выдачи, документы, квалификации и назначения не создаются из строк таблицы.
