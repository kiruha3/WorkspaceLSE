# Распаковка автономного комплекта без tar/xz

Владелец получил ошибку `Can't initialize filter; unable to run program "xz -d -qq"` при распаковке `postgres-windows-x86_64.txz` в наборе `62b2ad4`. На проверочной машине `C:\Windows\System32\tar.exe` поддерживал этот архив самостоятельно; это не гарантировало работу другой версии tar на целевой Windows. Установщик ошибочно зависел от внешнего распаковщика.

## Исправление

- `installation/archive_tools.py` использует только стандартные `zipfile`, `tarfile`, gzip/lzma Python 3.13.
- PostgreSQL читается непосредственно из JAR/ZIP и вложенного XZ-потока; промежуточная распаковка через внешние процессы отсутствует.
- npm-кэш извлекается и создаётся тем же helper-скриптом.
- Windows-пути получают extended-length-префикс, чтобы длинные имена кэша не зависели от Win32-ограничения обычных путей.
- Сохраняются проверка хешей пакетов, offline-режим зависимостей и запрет свежей установки поверх существующей БД.

## Проверки

Три новых регрессионных теста сначала упали без helper-скрипта, после исправления прошли. Подпроцессы тестов работают с пустым PATH:

1. Настоящий ZIP/JAR с вложенным XZ-архивом PostgreSQL извлекается без `tar`/`xz`.
2. Gzip-кэш с итоговым путём длиннее 260 символов извлекается и читается.
3. Создание npm-архива включает только `_cacache`, исключая соседний лог.

Шесть прежних проверок манифеста зависимостей также прошли. Дополнительный регрессионный случай воспроизводит Windows-ошибку обработки вложенных записей-каталогов в extended-length-пути; имена нормализуются до применения их метаданных.

На настоящих пакетах выполнен полный автономный проход в длинном пути вида `.runtime/extractor-smoke-.../WorkspaceLSE-windows-x64-offline-62b2ad4/WorkspaceLSE`. В проверочном PowerShell вызовы `tar.exe`/`xz.exe` заменены функциями, немедленно выбрасывающими ошибку; внешние прокси недоступны, пользовательские кэши пусты. PostgreSQL 17.11 распакован, установлены зависимости, применены миграции, создан setup с проверенным начальным паролем и 11 сотрудников. Экспертиз — 0. Django check, TypeScript и production-сборка прошли. Тестовая PostgreSQL на 55433 остановлена; рабочий сервер не перезапускался.

Для старого комплекта нужен небольшой патч с двумя файлами: `installation/Install.ps1` и `installation/archive_tools.py`. Бинарные установщики и библиотеки не менялись.
