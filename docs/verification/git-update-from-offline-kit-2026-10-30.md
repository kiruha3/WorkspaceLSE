# Обновление установленного ZIP-комплекта через Git

Инструкция `docs/RUNNING.md`, раздел 8, дополнена разовым подключением уже развёрнутой ZIP-папки к `origin/master`. Также уточнены полный корень распаковки, повторный запуск PostgreSQL после перезагрузки, исторический отдел 1, чтение нового снимка Google и применение выбранных изменений. `installation/README.md` содержит краткий порядок установки, импорта, сетевого доступа и обновления; из корневого README добавлена ссылка.

## Проверенная процедура

Для ZIP исходная ревизия берётся из `BUNDLE.txt`. Создаётся локальная Git-метаинформация и загружается история. `reset --mixed` устанавливает исходную ревизию без замены файлов рабочего дерева. Перед stash проверяется, что `.runtime/`, документы, резервные копии и каталоги зависимостей игнорируются. Локальные исправления исходников и отдельные скачанные файлы сохраняются в stash; затем выполняется `pull --ff-only origin master`. Старые локальные исправления автоматически поверх новой версии не применяются.

Обычное обновление использует комплектный uv с запасным вариантом глобального uv, синхронизацию по lock-файлам, npm ci, запуск существующей PostgreSQL, миграции, Django check и сборку фронтенда. Свежая установка и bootstrap повторно не выполняются. При ошибке любого шага обновления PowerShell останавливается.
