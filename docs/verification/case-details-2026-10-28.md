# Сведения дела и справочники

Этап добавляет сведения назначившего органа, дела, материалов, вопросов и основания3214-р в обычную карточку экспертизы. Эти же данные читает отчёт15.1. Отдельная запись WorkCaseDetails связана с Expertise один-к-одному; изменения сохраняются в CaseDetailsRevision. Номера, состояние, фактический отдел, люди, окончания и выдачи этой командой не меняются.

## Работа в интерфейсе

В карточке экспертизы доступен раздел «Сведения дела». До ручного уточнения он показывает сохранённые сведения журнала; после уточнения — текущие значения с историей «было → стало». Очистка поля не возвращает прежнее значение из источника. Текст вопросов не пересчитывает Q/R/S/T автоматически.

Действие доступно по существующему expertise.work.update для открытой работы и expertise.closed.correct для закрытой, в разрешённой области. Исторический участник может уточнить свою работу без создания нативного назначения. После выдачи разрешено исправление этих метаданных, не принятого заключения или факта выдачи. Новых прав или назначений ролей этап не создаёт.

Признак3214-р имеет три значения: неизвестно, нет, да. Для «да» требуются пояснение и доступный подтверждающий документ. Загруженная копия требует сохранённого файла; бумажный оригинал допустим без скана. Категории1/5 не означают3214-р автоматически. Отчётная группа органа не выводится из названия организации.

Экран `/references` содержит12 справочников с поиском, активностью, постраничным просмотром и историей. Управление доступно по references.manage, просмотр по references.view/manage. Коды неизменяемы, удаления нет. Типы органов имеют явно выбранную отчётную группу; неопределённая группа не считается «иной». Направление/отдел журнала переписки и правило снятия с контроля задаются при создании.

## API и согласованность

GET `/api/v1/expertises/<id>/case-details/` возвращает варианты типов органов. Полный POST принимает версию, основание изменения, текстовые сведения, authority_type_id и явные поля3214. Данные, новая версия работы, история и аудит фиксируются атомарно, под блокировками материала/поступления/работы/профиля/документа/справочника. Повтор ключа не создаёт вторую редакцию, текущие права и доступ к документу проверяются и при повторе.

POST/PATCH справочников поддерживают необязательный Idempotency-Key, сохраняя прежних клиентов без заголовка. GET `/api/v1/references/<catalog>/<id>/history/` не разрешён пользователю только на основании доступа к вариантам рабочей формы.

Обе веб-формы сохраняют исходный пакет и ключ после потери ответа. Определённый конфликт409 сохраняет ввод и требует явного принятия свежей версии. Смена карточки не позволяет позднему ответу заменить новую карточку. Ручное уточнение дела блокирует последующее автоматическое замещение этой работы новым снимком журнала, даже если прежние scalar-поля совпадают.

Без профиля остаётся точное сопоставление известной метки старого журнала. Раздел1 дополнен12 клетками графыP3214-р: registry содержит816 клеток, расчёт из снимка журнала остаётся660. ## Отложенные небольшие замечания

- Снимок аудита хранит код отдела из номера, а не отдельныйID/код фактического work.department. Сама команда фактический отдел не меняет; происхождение снимка нужно уточнить отдельной правкой.
- Главная для роли только со справочниками может показывать устаревшую подсказку об отсутствии рабочих разделов при работающей ссылке на справочники.
- Vite предупреждает о едином JS-блоке520.44кБ (145.16кБ gzip); сборка успешна, разделение загрузки маршрутов отложено.

Два небольших замечания предыдущего исторического редактора не исправлялись этим этапом: видимость комментария возврата без даты/причины и одинаковый текст истории при замене только ссылки подтверждения.
