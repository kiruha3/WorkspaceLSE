# Продолжение установки после отказа initdb в доступе

Пользовательский комплект: `WorkspaceLSE-windows-x64-offline-62b2ad4`. После исправления XZ-распаковки зависимости установились, но PostgreSQL сообщил `could not create directory .../.runtime/postgresql-data: Permission denied`. Учётная запись называлась «Администратор»; пользователь сообщил об обычном запуске PowerShell. К целевой машине прямого доступа нет.

## Изменения

- `installation/Complete-Setup.ps1` продолжает установленный комплект с создания/запуска БД: миграции, каталоги, идемпотентный bootstrap и сборка интерфейса. Системные инструменты и Python/npm-зависимости повторно не устанавливает.
- Если кластер ещё не инициализирован, скрипт выдаёт текущему SID явный `Modify` на `.runtime/` и дочерние элементы через `icacls /grant *SID:(OI)(CI)M /T /C /Q /L`. Другие ACL сохраняются; нет разрешений Everyone/Users и изменения прав всего диска. Для инициализированного кластера ACL пропускается; корневая junction не обрабатывается.
- Файл можно запускать из `installation/` либо положить в корень старого проекта под именем `Complete-AIS-Setup.ps1`. Удалять БД или заменять старый runtime для продолжения не требуется.
- `infra/local.py` и временная совместимая обёртка старого runtime в файле продолжения выводят нативную диагностику PostgreSQL и сохраняют её в `.runtime/postgresql-{program}.log`. Аргументы команд в эти логи не записываются.
- Нативный вывод направлен в обычный файл. Проверка обнаружила зависание старого запуска при наследовании отсоединённым сервером потоков PowerShell; файл устраняет ожидание конца pipe после завершения `pg_ctl`.
- Полный `Install.ps1` использует тот же этап продолжения. `uv pip sync --link-mode=copy` устраняет предупреждение о невозможности hardlink между разными дисками при автономной установке.

## Проверки

1. Три unit-теста нативной диагностики: ненулевой код с текстом ошибки и логом; допустимый ненулевой статус `pg_ctl status`; успешный вывод. До исправления две проверки падали, после изменения все проходят.
2. Три теста распаковки архивов Python и шесть проверок автономных зависимостей проходят. `Install.ps1 -CheckOnly` подтверждает пять установщиков и 18 файлов зависимостей. PowerShell 5.1 разбирает оба сценария без ошибок.
3. Отдельная копия проекта по длинному пути `.runtime/permissions-smoke-*/WorkspaceLSE-windows-x64-offline-62b2ad4/WorkspaceLSE`, отдельный PostgreSQL на `127.0.0.1:55433`. Зависимости переиспользованы из остановленной проверочной установки, сетевые загрузки отключены настройками offline/proxy. Новая БД создана после выдачи прав. Явный ACE текущего SID содержит `Modify, Synchronize`, наследование файлов и каталогов, не является унаследованным.
4. Файл продолжения со старым `infra/local.py` коммита `b493e54` проходит миграции, seed-команды, bootstrap, Django check и сборку Vue/TypeScript. Начальное состояние: 11 карточек сотрудников, 0 экспертиз, 4 способа выдачи.
5. Обновлённый `infra/local.py` непосредственно останавливает и запускает этот отдельный кластер, возвращая управление без зависания. Повторный запуск скачиваемого файла из корня проекта завершается успешно: хеш пароля setup, локальный файл входа и проверенные количества записей не меняются.
6. Проверочный PostgreSQL штатно остановлен. Основная рабочая БД, пользователи и веб-серверы не изменялись.

Проверка выполнена на текущей машине под `kirill` с уже установленными совместимыми системными инструментами. Токен встроенной учётной записи «Администратор» на целевой машине недоступен для воспроизведения. Успешное завершение установки на машине пользователя требует запуска переданного файла и не утверждается этим отчётом. Сборка фронтенда сохраняет прежнее предупреждение Vite о размере JS-чанка; ошибок сборки нет.
