## Сквозной путь

Эксперт сохраняет результат с причиной полного СНДЗ либо распределением нерешённых вопросов → подтверждает окончание с файлом → последнее WorkClosure фиксирует принятую редакцию → registry читает именно её причины одним SQL SELECT → пользователь отчётности раскрывает число/пустоту и видит связанные карточки → Excel получает те же значения в исходном бланке.

Решение без исполнения и его причина фиксируются отдельной командой. Причина возврата не является причиной СНДЗ; дата выдачи не заменяет дату решения. Новый черновик не меняет принятое закрытие. Исправление принятого результата/распределения меняет fingerprint, прежняя ссылка выгрузки даёт409. Registry-v2 включает версию правил в fingerprint; старый journal-v1 сохраняет660 клеток и прежние правила.

Полный СНДЗ считается один раз по работе, не по числу вопросов. Для вопросов суммируется принятое распределение T: при T>0 нужна подтверждённая полнота, уникальные известные причины и сумма=T; известное T=0 с пустым распределением даёт нули. Неизвестное T/неполное/противоречивое/несопоставленное распределение даёт пустые причинные графы. Новый справочный код не становится «иным» автоматически. Уже принятый неактивный код считается по семантике, а не изменяемому названию.
