# Приёмка → регистрация → назначение

Все пути ниже имеют префикс `/api/v1`. Сессия пользователя общая с существующим входом Django; для команд необходим CSRF. UUID не заменяет проверку прав. Списки фильтруются до пагинации, детали и команды проверяются отдельно.

## Шаги и данные

1. `POST /documents/`: `kind=resolution|decision`, название, `source_kind=paper_original|uploaded_copy`, необязательный `department_id`. Это метаданные основания, ещё не поступление и не номер экспертизы.
2. Для копии `POST /documents/{id}/versions/` — multipart `expected_version` и `file`. Требуется фактически сохранённая версия. Для бумажного оригинала файл можно добавить позднее. Оригинал и все прежние версии сохраняются.
3. `POST /receipts/`: дата поступления, отправитель, название материала, отдел и основание. Создаётся черновик и самостоятельный материал. `GET /receipts/` / `/{id}/` возвращают сохранённое состояние.
4. `POST /receipts/{id}/register/` с `expected_version` принимает поступление, но **не закрепляет номер**. Нужен бумажный оригинал или сохранённый файл копии. Уточнение через `POST /receipts/{id}/amend/` требует версию и непустую причину; принятое поступление нельзя лишить основания.
5. `POST /receipts/{id}/expertises/` закрепляет вручную номер и специальность. Тело: `expected_version` поступления, `registration_number`, `department_id`, `specialty_id`, `appointment_nature=primary|repeated|additional`, `is_commission`; отдельно `historical_number` и `complex_group_id` при наличии. В заголовке нужен `Idempotency-Key`. Поступление уже должно быть принято.
6. `GET /expertises/{id}/assignment-candidates/` возвращает только минимальный каталог: ID, имя, пригодность и причину блокировки. `POST /expertises/{id}/assignments/` с версией работы, `employee_ids` и причиной назначает состав. `/reassign/` меняет текущий состав без смены номера.

Текущий номер строго `N/отдел-категория-ГГ`. Категории 1–6, выбранный отдел совпадает с номером. Номер в скобках не разбирается как текущий; его помещают в отдельное историческое поле. Первая часть номера — общая последовательность учреждения за год, независимо от отдела и категории. `GET /expertises/number-hint/?department_id=…&year=2026` возвращает максимальный номер учреждения за год в `last_number` (или `null`) и `next_sequence` — следующий порядковый номер (1 для пустого года). Учебные материалы исключаются. `department_id` сохраняется для проверки права регистрации в выбранном отделе, но не ограничивает поиск максимума. Подсказка не резервирует номер. В форме можно выбрать категорию дела и год и нажать «Подставить номер»: кнопка запрашивает свежий максимум и заполняет полный номер с выбранным отделом; для комплекса — все строки последовательными номерами с отделом каждой строки. Изменение категории/года само по себе не заменяет введённые номера. Ручной ввод и прежняя проверка уникальности полного номера сохраняются; новые поля в БД не добавляются.

## Самовольное строение ·3214-р

Регистрация дополнительно принимает необязательный bool `decree3214`: явная отметка «Самовольное строение» для16.1/16.2. При переданном поле создаётся профиль сведений дела и одна редакция; повтор по тому же ключу редакцию не дублирует. Старое тело без поля работает как прежде. Новая отметка `true` для другой или неизвестной специальности отклоняется атомарно. Форма скрывает и сбрасывает отметку при выборе другой специальности.

Редактирование выполняется существующей командой `POST /expertises/{id}/case-details/`, с прежними правами, версией и историей. Дополнительный документ и пояснение необязательны. Выбранный документ по-прежнему проверяется на доступ и наличие оригинала/копии. У `false`/`null` не остаются реквизиты отметки. Существующую старую отметку другой специальности можно сохранить при правке остальных сведений, но отчёт её не учитывает.

Графа3214-р раздела1 учитывает законченные заключения только по16.1/16.2 с явным `true`. Без отметки в этой графе0, а не обязательный вопрос, блокирующий расчёт. Это не подтверждение полноты остальных граф. Старым работам признак автоматически не назначается.

## Комиссия и комплекс

Перед первой попыткой регистрации интерфейс запрашивает свежий следующий порядковый номер за год, указанный в текущем номере. При отклонении показывает введённый и ожидаемый номера и требует явного выбора «Исправить номер» или «Да, зарегистрировать». В комплексе проверяется каждая строка относительно общей последовательности; до подтверждения пакет не отправляется. Подтверждённое отклонение разрешено, ручной номер не исправляется автоматически. Подтверждение привязано к текущему содержимому формы и сбрасывается при изменениях. При потерянном ответе повторяется тот же ключ и пакет без ложного сравнения с уже сохранённой собственной работой; после явного отказа4xx очередность проверяется заново. Это предупреждение интерфейса, оно не заменяет серверную проверку формата, уникальности и прав, а также не резервирует номер. Миграции и дополнительные поля БД не требуются.

Комиссия — одна работа и один номер, минимум два квалифицированных участника. Обычная работа — один участник. Комплекс создаётся `POST /complex-groups/` с `receipt_id` и обязательным непустым названием; группа сама по себе номера не получает. `Idempotency-Key` поддерживает повтор после потерянного ответа и конфликтует при другом содержимом команды; прежние клиенты без ключа поддерживаются. Повторное создание с тем же названием в одном материале (без учёта регистра) возвращает существующее объединение, в том числе при одновременных запросах; лишних записей и событий создания не появляется. Работы одной группы относятся к одному материалу, в группе нельзя повторно зарегистрировать ту же специальность. Вторая специальность — отдельная регистрация, не второй участник той же специальности.

В интерфейсе после отметки «Комплексная экспертиза» появляются две строки номеров по умолчанию, дополнительные добавляются кнопкой. Отдельного выбора/создания объединений нет. `POST /receipts/{id}/complex-expertises/` принимает `expected_version` и `works[]` (не менее двух строк: номер, отдел, специальность, характер назначения, комиссионность; исторический номер и 3214-р необязательны). Ответ — `expertises[]`. Каждая строка проходит обычную проверку регистрации и права своего отдела. Специальности и порядковые номера различаются; год и категория дела совпадают. В форме характер назначения и комиссионность общие, остальные сведения задаются по строкам.

Команда требует `Idempotency-Key`. Пакет, техническое объединение и события сохраняются одной транзакцией: ошибка второй или последующей строки откатывает всё. Повтор того же пакета возвращает те же работы; новый payload с прежним ключом даёт409. Техническое название объединения нейтрально, номера находятся в `complex_group.expertises[]` и фильтруются по текущему праву чтения. Реестр показывает каждый номер отдельной строкой, карточки содержат ссылки на доступные номера комплекса. Модели не изменены, миграции не требуются.

В архиве документов `POST /expertises/{id}/documents/` дополнительно принимает `share_with_complex=true`: существующий документ связывается со всеми работами комплекса, без повторной загрузки файла. Нужны права чтения и связывания на каждый номер; отказ атомарный. Существующие связи пропускаются, результат и завершение экспертиз не изменяются. В интерфейсе это явный флажок «Прикрепить ко всем номерам комплекса»; при отсутствии полномочий он недоступен с пояснением.

## Допуск и доступ

Назначение проверяет активность сотрудника и специальности, статус `qualified`, дату получения при наличии и известный срок действия. Подтверждённое получение без даты допустимо с непустым основанием. `training` / `unknown_legacy` не допускаются. Перед записью сведения повторно проверяются под блокировкой. В назначении остаётся снимок квалификации; последующие кадровые изменения его не переписывают.

Перепоручение закрывает только удалённых участников и создаёт только добавленных. Неизменённый допустимый участник сохраняет ID назначения. Прежний исполнитель остаётся в истории, но без другого права перестаёт видеть работу в текущей выборке «свои». Явное изменение состава повторно проверяет всех выбранных участников; исключения для утратившей силу квалификации не вводились.

Должность не выдаёт полномочия автоматически. Права `expertise.view`, `expertise.assign`, `expertise.reassign`, `expertise.register` имеют независимые области. Просмотр учреждения не расширяет назначение за пределы разрешённых отделов. Общий материал не даёт прав на соседние работы. Основание читается по собственному праву документа либо через доступную связанную работу с `documents.view`; право просмотра файла не даёт изменение общего файла.

В карточке сервер отдаёт `allowed_actions` только для реализованных команд. Отсутствие исполнителя — отдельный факт; исходное состояние работы `in_progress`, не выдуманный итоговый статус.

## Конфликты и сохранение

- Успех загрузки файла, приёмки и закрепления номера — три независимых подтверждения. Сохранённый файл не удаляется, если дальнейшая регистрация не состоялась.
- Несовпадение `expected_version` даёт 409; черновик формы не теряется. Повторная загрузка свежих сведений выполняется явно.
- Один ключ регистрации с тем же payload возвращает исходный бизнес-результат; другой payload с тем же ключом — 409. Неуспешная команда не оставляет успешной записи повтора. Права проверяются снова и при повторе; видимость документа и доступные действия проецируются по текущим правам. Деактивация справочной специальности не отменяет ответ уже выполненной команды, но блокирует новую регистрацию.
- Загрузка версии также поддерживает `Idempotency-Key`; новый клиент сохраняет пару ключ/попытка до подтверждения. Сервер сопоставляет документ, ожидаемую версию, имя, размер и SHA256 содержимого. Потерянный ответ восстанавливает ту же версию, другое содержимое с тем же ключом конфликтует. Старые клиенты без ключа сохраняют обычную проверку версии.
- Одновременная попытка одинакового номера даёт один результат и управляемый конфликт, не дубль/500.
- Неподдерживаемый предпросмотр не заменяет оригинал: можно скачать файл. PDF/PNG/JPEG показываются в карточке после проверки доступа; статического публичного media-маршрута нет.

Реестр поддерживает поиск, отдел/специальность/текущего исполнителя и включительный период поступления. `/expertises/filter-options/` даёт исполнителей только из разрешённой текущей выборки. Другие фильтры, жизненный цикл, произвольные документы/переписка, выдача, импорт и 15.1 остаются следующими этапами.
