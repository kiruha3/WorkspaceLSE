# Приёмка → регистрация → назначение

Все пути ниже имеют префикс `/api/v1`. Сессия пользователя общая с существующим входом Django; для команд необходим CSRF. UUID не заменяет проверку прав. Списки фильтруются до пагинации, детали и команды проверяются отдельно.

## Шаги и данные

1. `POST /documents/`: `kind=resolution|decision`, название, `source_kind=paper_original|uploaded_copy`, необязательный `department_id`. Это метаданные основания, ещё не поступление и не номер экспертизы.
2. Для копии `POST /documents/{id}/versions/` — multipart `expected_version` и `file`. Требуется фактически сохранённая версия. Для бумажного оригинала файл можно добавить позднее. Оригинал и все прежние версии сохраняются.
3. `POST /receipts/`: дата поступления, отправитель, название материала, отдел и основание. Создаётся черновик и самостоятельный материал. `GET /receipts/` / `/{id}/` возвращают сохранённое состояние.
4. `POST /receipts/{id}/register/` с `expected_version` принимает поступление, но **не закрепляет номер**. Нужен бумажный оригинал или сохранённый файл копии. Уточнение через `POST /receipts/{id}/amend/` требует версию и непустую причину; принятое поступление нельзя лишить основания.
5. `POST /receipts/{id}/expertises/` закрепляет вручную номер и специальность. Тело: `expected_version` поступления, `registration_number`, `department_id`, `specialty_id`, `appointment_nature=primary|repeated|additional`, `is_commission`; отдельно `historical_number` и `complex_group_id` при наличии. В заголовке нужен `Idempotency-Key`. Поступление уже должно быть принято.
6. `GET /expertises/{id}/assignment-candidates/` возвращает только минимальный каталог: ID, имя, пригодность и причину блокировки. `POST /expertises/{id}/assignments/` с версией работы, `employee_ids` и причиной назначает состав. `/reassign/` меняет текущий состав без смены номера.

Текущий номер строго `N/отдел-категория-ГГ`. Категории 1–6, выбранный отдел совпадает с номером. Номер в скобках не разбирается как текущий; его помещают в отдельное историческое поле. `GET /expertises/number-hint/?department_id=…&year=2026` возвращает `last_number` или `null`, ничего не резервируя.

## Комиссия и комплекс

Комиссия — одна работа и один номер, минимум два квалифицированных участника. Обычная работа — один участник. Комплекс создаётся `POST /complex-groups/` с `receipt_id` и названием; группа сама по себе номера не получает. Работы одной группы относятся к одному материалу, в группе нельзя повторно зарегистрировать ту же специальность. Вторая специальность — отдельная регистрация, не второй участник той же специальности.

## Допуск и доступ

Назначение проверяет активность сотрудника и специальности, статус `qualified`, дату получения при наличии и известный срок действия. Подтверждённое получение без даты допустимо с непустым основанием. `training` / `unknown_legacy` не допускаются. Перед записью сведения повторно проверяются под блокировкой. В назначении остаётся снимок квалификации; последующие кадровые изменения его не переписывают.

Перепоручение закрывает только удалённых участников и создаёт только добавленных. Неизменённый допустимый участник сохраняет ID назначения. Прежний исполнитель остаётся в истории, но без другого права перестаёт видеть работу в текущей выборке «свои». Явное изменение состава повторно проверяет всех выбранных участников; исключения для утратившей силу квалификации не вводились.

Должность не выдаёт полномочия автоматически. Права `expertise.view`, `expertise.assign`, `expertise.reassign`, `expertise.register` имеют независимые области. Просмотр учреждения не расширяет назначение за пределы разрешённых отделов. Общий материал не даёт прав на соседние работы. Основание читается по собственному праву документа либо через доступную связанную работу с `documents.view`; право просмотра файла не даёт изменение общего файла.

В карточке сервер отдаёт `allowed_actions` только для реализованных команд. Отсутствие исполнителя — отдельный факт; исходное состояние работы `in_progress`, не выдуманный итоговый статус.

## Конфликты и сохранение

- Успех загрузки файла, приёмки и закрепления номера — три независимых подтверждения. Сохранённый файл не удаляется, если дальнейшая регистрация не состоялась.
- Несовпадение `expected_version` даёт 409; черновик формы не теряется. Повторная загрузка свежих сведений выполняется явно.
- Один ключ регистрации с тем же payload возвращает исходный результат; другой payload с тем же ключом — 409. Неуспешная команда не оставляет успешной записи повтора. Права проверяются снова и при повторе.
- Одновременная попытка одинакового номера даёт один результат и управляемый конфликт, не дубль/500.
- Неподдерживаемый предпросмотр не заменяет оригинал: можно скачать файл. PDF/PNG/JPEG показываются в карточке после проверки доступа; статического публичного media-маршрута нет.

Реестр поддерживает поиск, отдел/специальность/текущего исполнителя и включительный период поступления. `/expertises/filter-options/` даёт исполнителей только из разрешённой текущей выборки. Другие фильтры, жизненный цикл, произвольные документы/переписка, выдача, импорт и 15.1 остаются следующими этапами.
