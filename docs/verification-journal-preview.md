# Проверка предпросмотра переноса журнала

Общая цель — основной журнал в Django, полный рабочий процесс и серверный отчёт 15.1 — остаётся незавершённой. Предпросмотр является подготовкой исторического переноса, не заменяет его и не создаёт рабочие экспертизы.

## Чтение и нормализация

Первый прогон новых проверок остановился на отсутствующих модулях. После минимальных контрактных заглушек получены 62 падающих проверки отсутствующего чтения/нормализации/CLI; ошибочная тестовая фикстура счётчика SQL получила явный доступ к тестовой БД, чтобы действительно проверять ноль запросов. После реализации 61 проверка прошла, одна выявила некорректный порядок ячеек в созданном тестовом OOXML: J оказался после P, библиотека не могла прочитать оставшиеся колонки. Диагностика raw на границе читателя подтвердила причину, исправлен порядок именно фикстуры, утверждения сохранены. Затем прошли62 проверки.

Ещё три проверки сначала воспроизвели пропуск предупреждения о формуле без кэша, падение всей операции на 5000-значном номере и принятие Excel serial110000 за дату 2201 года. Исправлены конкретные границы: неизвестный кэш не заменяется числом, длинный номер становится ошибкой своей строки, для числовых дат проверяется тот же диапазон годов. Расширенный прогон: **65 из65**. Итог первой части: **367 серверных тестов за441,27с**, Django check без замечаний, дрейфа миграций нет, коммит `225431f`.

Чтение XLSX выполняется openpyxl3.1.5 в read-only режиме, CSV — стандартной библиотекой. Добавлен один Python-пакет и его зависимость et-xmlfile2.0.0, lock обновлён. Источник не сохраняется обратно, дополнительные службы не запускаются. CLI по умолчанию выводит только метаданные/сводку, не тексты дел; подробные строки требуют явного `--include-rows`.

## Итоговое ревью и исправления

Один независимый read-only reviewer проверил весь срез `ccb7a8c..9ea4d14` по спецификации, плану и зафиксированным решениям. Критических замечаний нет; четыре существенных подтверждены:

1. Заниженные размеры листа в XLSX могли скрывать строки и колонки. Теперь проверяются физические координаты, затем размеры производителя сбрасываются перед чтением. Превышение лимита отвергается, а не обрезается.
2. Формула без кэша в B:X могла исчезнуть вместе со строкой. Теперь формула считается содержимым строки; шаблонная формула только Z по-прежнему не создаёт регистрацию.
3. Стиль даты превращал Excel serial60 в правдоподобную дату до нормализации. Узкая проверка XML первого листа сохраняет исходные числовые C/P и кэш формул. Проверены 59/60/61 с форматированием даты для1900/1904 и обычных/формульных ячеек.
4. Ошибка внутри стандартной записи файла могла оставить частичные байты без снимка. Локальная граница владеет файлом с момента исключительного создания; при ошибке записи/закрытия удаляет его, не трогая прежний исходник.

Сначала **17 новых регрессионных проверок упали**, затем прошли. Расширенный набор источника, нормализации, API, конкурентного повтора и учебных ролей: **101 из101**. Повторный read-only CLI на оригинале по-прежнему даёт466 строк, хеш не изменился. Общий серверный прогон после исправлений: **399 из399 за453,31с**, Django check без замечаний, дрейфа миграций нет. Второго ревью не назначалось.

Отложенное небольшое замечание: при ошибочном текущем номере исторический номер пока не выделен в facts, но полный B сохранён и ошибка видна. Это не подмена текущего номера историческим.

Поведения, не принятые за закрытые этим срезом: историческое применение/15.1 остаются следующими обязательными частями; восстановление после жёсткого завершения процесса — эксплуатационный пробел; привилегированное изменение SQL/ORM вне API не заблокировано; оригинал после скачивания может исполняться сторонним Excel, в веб-предпросмотре ячейки не исполняются. Для XML-адаптера используется путь первого листа через private API openpyxl3.1 — при обновлении пакета эта интеграция требует регрессионной проверки. Для другого storage требуется явная замена локальной файловой границы.
