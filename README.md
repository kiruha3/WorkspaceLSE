# АИС ФГБУ Абаканская ЛСЭ

Каталог нового самостоятельного проекта: Django backend и Vue frontend в одном репозитории внутри `E:/VLSE`.

Рабочие срезы: персональный вход и кадровый учёт; приёмка с документом-основанием → ручная регистрация → назначение/перепоручение по квалификации → производство и сроки → результат, завершение и корректировка → проверенный комплект и отдельный факт полной выдачи. Отдельно работает переписка: черновик → регистрация → отправка и получение → явное закрытие контроля ответа. Django API, PostgreSQL и Vue находятся в самостоятельном репозитории, ветка `implementation`; push нет.

Структура: `backend/`, `frontend/`, `infra/`, `docs/`. Исходные проекты `../web-vue`, `../labalse` и `../labalse_front` сохраняются без переноса и удаления.

Согласованный путь сначала проверяется в [локальном кликабельном макете](../web-vue/docs/mockups/expertise-workflow-v1/prototype/index.html). Его действия учебные и не заменяют серверный учёт.

## Что уже работает

- Вход по Django session с CSRF, выход, немедленное применение отзыва прав на следующем запросе.
- Роли с отдельной областью каждого действия; назначение и прекращение роли сотрудника, даты и аудит.
- Сотрудник с несколькими должностями и специальностями; обучение отдельно от полученной квалификации.
- Явное подтверждение специальности по праву; обучение не даёт допуска к назначению на экспертизу. Получение можно подтвердить с основанием без известной даты; дата остаётся пустой, известный срок действия проверяется.
- Создание персонального входа без автоматической выдачи ролей; блокировка входа отдельно от активности сотрудника.
- Добавление и деактивация справочных отделов, должностей, специальностей через API.
- Проверка версии при изменении роли, сотрудника, квалификации и кадровых назначений.
- Приёмка с бумажным оригиналом либо сохранённой копией/фотографией постановления или определения; уточнение с причиной, позднее добавление скана.
- Хранение исходных файлов и версий; просмотр PDF/изображений внутри карточки, авторизованное скачивание оригинала.
- Ручное закрепление номера `N/отдел-категория-ГГ`, исторический номер отдельно, подсказка без резервирования. Защита от дубля номера и повторного запроса.
- Одна комиссия — один номер, минимум два квалифицированных участника. Комплекс — отдельный номер по каждой специальности.
- Назначение/перепоручение с проверкой фактической квалификации, состояния и версии; прежние исполнители сохраняются в истории, текущая выборка перемещается получателю.
- Реестр экспертиз с поиском и фильтрами отдела, специальности, текущего исполнителя и дат поступления; параметры сохраняются при возврате из карточки.
- Приостановки/возобновления своей работы по правам, с датой, причиной, историей и проверкой версии. Повтор команды не создаёт второй факт.
- Исходный, запрошенный и согласованный сроки отдельно. Запрос не меняет действующий срок; согласование требует бумажного оригинала или сохранённой копии документа.
- Календарный счётчик с явно указанным методом и датой расчёта, фильтры состояния и диапазона календарных дней. Это не юридический или рабочий календарь.

- Редакции результата: заключение, полный СНДЗ либо акт исследования по категории; Q/R/S/T, сложность и отдельные расширяемые справочники причин. Пустое число остаётся неизвестным, а не нулём.
- Завершение с датой и сохранённым файлом, отдельное решение без исполнения; исправление закрытой работы отдельным правом, без перезаписи истории или фиктивной выдачи. Неизвестные отчётные сведения остаются явными пробелами.
- Счётчики и фильтры дней для закрытой работы используют подтверждённый конец; незакрытая пауза ограничивается им без выдуманного возобновления.
- Переписка: самостоятельные и связанные письма, редакции черновика, ручная регистрация, принятые версии файлов, отправка отдельным адресатам, получение и доставка. Частичные/дополнительные/завершающие ответы и явное закрытие/возобновление контроля с историей.

- Выдача: неполный черновик комплекта всех работ материала, редакции, отдельная проверка принятых версий, фактическая дата/способ/получатель/основание и подтверждение. Изменение состава делает проверку устаревшей, незавершённая работа блокирует выдачу. Неутверждённые комплекты 4/6, СНДЗ, возврата и комиссии явно требуют уточнения.

Исторический журнал уже перенесён:472 реальные регистрации с исходными номерами/отделами и связями людей, без выдуманных назначений/дат. На `/reports` работает предварительный серверный15.1 из рабочей БД, отдельный режим снимка и Excel в исходном бланке; явно учебные материалы исключаются. Проверки: [перенос](docs/verification/real-journal-transfer-2026-10-28.md), [отчёт из БД и его ограничения](docs/verification/form151-registry-2026-10-28.md).

Пока не реализованы: синхронизация изменившихся строк нового снимка с рабочими записями, оставшиеся виды документов и подключённые папки/URL, неутверждённые варианты и исправление после выдачи; не все графы15.1 сопоставлены, разделы7–8 отсутствуют. Предварительная выгрузка не означает готовность официальной формы. Общая цель остаётся незавершённой. Проверки: [производство и сроки](docs/verification-production.md), [результаты и завершение](docs/verification-results.md), [переписка и контроль](docs/verification-correspondence.md), [выдача материалов](docs/verification-issuance.md).

## Локальный запуск без VM и Docker

Требуются Python 3.13/uv, Node.js/npm и переносимые PostgreSQL 17 binaries в `.runtime/postgresql/{bin,lib,share}`. Использованный Windows runtime: `io.zonky.test.postgres:embedded-postgres-binaries-windows-amd64:17.11.0` из Maven Central; PostgreSQL 17.11. Архив содержит TXZ с указанными каталогами. Рабочие файлы старых проектов не используются.

Из корня проекта:

```powershell
uv sync --directory backend --python 3.13
& ./backend/.venv/Scripts/python.exe infra/local.py db-start
& ./backend/.venv/Scripts/python.exe infra/local.py backend manage.py migrate --noinput
& ./backend/.venv/Scripts/python.exe infra/local.py backend manage.py seed_result_catalogs
& ./backend/.venv/Scripts/python.exe infra/local.py backend manage.py seed_issue_catalogs
& ./backend/.venv/Scripts/python.exe infra/local.py bootstrap --seed-staff --with-personnel-role
& ./backend/.venv/Scripts/python.exe infra/local.py backend manage.py runserver 127.0.0.1:8000 --noreload
```

В другом терминале, из `frontend/`:

```powershell
npm.cmd ci
npm.cmd run dev
```

Адрес: http://127.0.0.1:5173/; страницы `/people`, `/roles`, `/access`, `/intake`, `/receipts/:id`, `/expertises`, `/expertises/:id` по правам текущего пользователя. Только один Vite на `0.0.0.0:5173`, прокси `/api` → Django на 8000. Django и PostgreSQL слушают **только loopback**, БД — порт 55432. Это окружение разработки, не готовая производственная конфигурация. Доступ по внешнему адресу зависит от сетевого маршрута и проброса 5173 на эту машину.

Для входа по адресу другого устройства сохраните разрешённые web-hosts и перезапустите Django: `infra/local.py web-hosts <белый-IP> <локальный-IP>`. Команда запускается тем же Python, что выше. При необходимости разрешения Windows существует `infra/allow-web-5173.ps1` для явного запуска из PowerShell от администратора; он не отключает firewall и не открывает БД.

Логин и случайный пароль настройки записываются в игнорируемый `.runtime/local-login.json`. Подключение к БД — отдельно в `.runtime/postgresql-connection.json`. Не публиковать эти файлы. `--with-personnel-role` явно совмещает администратора доступа и кадровый учёт для проверки; право читать экспертизы из этого не следует. Десять сотрудников предзаполнены без вымышленных логинов и ролей, специальности — `unknown_legacy`, без выдуманных дат получения.

Повторный bootstrap сохраняет изменённые роли, пароль и существующие записи. Он не является командой сброса или восстановления. Для другого начального пользователя: `bootstrap_access --username ... --full-name ...`, пароль через `AIS_BOOTSTRAP_PASSWORD` или интерактивный ввод. Остановить только эту БД: `infra/local.py db-stop`; данные остаются на месте.

### Проверка разных рабочих мест

`backend/.venv/Scripts/python.exe infra/local.py workflow-demo` создаёт пять явно обозначенных учебных профилей: `demo.clerk`, `demo.head3`, `demo.expert`, `demo.expert2`, `demo.trainee`. Общий случайный учебный пароль и адреса сохраняются в игнорируемый `.runtime/Демо-доступ-к-АИС.txt`. Это не персональные учётные записи сотрудников. Команда не создаёт экспертиз и не меняет реальных сотрудников, существующие пароли, отредактированные роли и квалификации.

`setup` остаётся администратором доступа/кадровиком, а не автоматическим делопроизводителем/начальником. Для регистрации войдите учебным делопроизводителем, для назначения — учебным начальником отдела 3, для своей карточки — учебным экспертом. Стажёр по 1.1 специально не допускается. При проверке обязательно отмечайте поступление как «Учебный материал»: подпись «ДЕМО» сама по себе не исключает его из отчёта. В этой БД уже есть472 реальные работы, не изменяйте их для учебных сценариев.

Новые права начальных шаблонов не дописываются автоматически в уже настроенные роли. Администратор назначает их явно через редактор. Контракты и ограничения вертикали: [приёмка и регистрация](docs/api-intake-registration.md).

Для уже существующей учебной роли эксперта можно явно добавить только два новых права результата: `backend/.venv/Scripts/python.exe infra/local.py workflow-demo --enable-results`. Если в этой роли есть неучебный сотрудник, команда откажется. Ранее отозванные остальные права не восстанавливаются. Корректировка закрытого результата требует самостоятельного назначения `expertise.closed.correct`; должность или создание файла её не дают.

Переписка доступна на `/letters`. Для уже существующих учебных ролей: `backend/.venv/Scripts/python.exe infra/local.py workflow-demo --enable-correspondence`. Флаг расширяет только учебные роли эксперта и делопроизводителя новыми правами переписки, не возвращает другие отозванные права и отказывается работать при неучебных участниках роли. Встроенный журнал не отправляет реальные email или письма в суды. Контракты и ограничения: [переписка и контроль](docs/api-correspondence.md), [проверка сценариев](docs/verification-correspondence.md).

## Проверки

Разбор первого листа старого журнала без записи в БД: `backend/.venv/Scripts/python.exe infra/local.py backend manage.py preview_journal "ПУТЬ.xlsx"` (или CSV). По умолчанию выводятся только хеш/метаданные/сводка. `--include-rows` явно выводит все исходные сведения в локальный stdout; не использовать его в общих логах. Это предпросмотр, не применение в рабочие экспертизы и не расчёт 15.1. [Проверки переноса](docs/verification-journal-preview.md).

Сохраняемый предпросмотр через сайт: `/imports` → «Проверить новый источник». Для существующего учебного делопроизводителя есть явный `backend/.venv/Scripts/python.exe infra/local.py workflow-demo --enable-import-preview`: только два новых права учреждения, без восстановления других отозванных прав и без расширения роли с реальными участниками. Видны оригинальные ячейки, разобранные факты, замечания, фильтры и скачивание исходника. Рабочие экспертизы и сотрудники при этом не создаются. [Контракт предпросмотра](docs/api-journal-preview.md).

Выдача доступна на `/issue-packages` и из карточки экспертизы. Для существующих учебных ролей есть явный `backend/.venv/Scripts/python.exe infra/local.py workflow-demo --enable-issuance`: только новые учебные права, без восстановления отозванных остальных прав или расширения реальных ролей. Контракт: [выдача](docs/api-issuance.md). Завершение, отправка письма, выставление счёта и выдача — разные факты.

```powershell
& ./backend/.venv/Scripts/python.exe infra/local.py backend -m pytest
& ./backend/.venv/Scripts/python.exe infra/local.py backend manage.py check
& ./backend/.venv/Scripts/python.exe infra/local.py backend manage.py makemigrations --check --dry-run
```

Из `frontend/`: `npm.cmd test`, `npm.cmd run typecheck`, `npm.cmd run build`. Backend tests используют отдельную тестовую PostgreSQL БД, включая сценарий настоящего HTTP-входа, создания роли, назначения и повторного чтения.

Спецификации: [система](docs/specification.md), [доступ](docs/access-control.md), [начальный состав и таблицы](docs/initial-data-and-tables.md), [применимые паттерны](docs/reference-patterns.md).
