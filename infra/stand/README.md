# Отдельный стенд АИС

Этот комплект запускает отдельные PostgreSQL, Django/Gunicorn и nginx. Google-таблица, рабочая БД, локальные файлы документов и Windows-настройки исходного стенда не переносятся.

Нужен Linux с работающим Docker Engine и Docker Compose v2. По умолчанию используется порт **8088** и отдельный Compose-проект `ais-lse-stand`. Сначала проверьте, свободен ли порт. Действующие службы сервера, включая `lanmessenger`, не требуется останавливать или перенастраивать.

## Первый запуск

Распакуйте `WorkspaceLSE-stand.tar.gz` в отдельный каталог, например `/opt/ais-lse-stand`, и перейдите в появившийся `WorkspaceLSE`:

```sh
python3 infra/stand/init_env.py --host 194.226.124.123 --port 8088
sh infra/stand/start.sh
```

Скрипт создаёт таблицы, 1200 вымышленных экспертиз за два года, сотрудников и роли, переписку, проекты комплектов выдачи, годовые планы и PDF-документы. Никакие строки Google/Excel не читаются. Повторный запуск не пересоздаёт записи и не сбрасывает пароли.

Доступ: `http://<IP>:8088/`, админка: `http://<IP>:8088/admin/`. Логин администратора — `admin`. Все сгенерированные пароли записываются только в `.stand-access/credentials.json`; этот каталог не обслуживается nginx и исключён из исходного архива. В том же файле доступны логины `clerk`, `head3`, `head4`, экспертов, стажёра и директора.

Внутри отдельного стенда вымышленные дела являются обычными рабочими записями, поэтому участвуют в отчёте 15.1. Учебный признак исключения из отчёта у них не выставляется. Это не импорт рабочей организации.

## Данные

- Вымышленные фамилии и должностные назначения; ни один сотрудник не берётся из журнала.
- Два отдела, семь специальностей, квалифицированные эксперты и стажёр без назначений.
- В работе, приостановлены, завершены, возвращены без исполнения; заключения, СНДЗ и акты исследований.
- Первичные, повторные, дополнительные, комиссионные и комплексные работы. У комплексной работы отдельные номера по специальностям с общим поступлением.
- Постановления/определения, заявления, результаты, подписки, сопроводительные, уведомления и счета; часть документов имеет созданные с нуля PDF-файлы.
- Входящие и исходящие письма, запросы на контроле, подготовленные комплекты выдачи.

## Обслуживание

```sh
docker compose --env-file infra/stand/.env -f infra/stand/compose.yml ps
docker compose --env-file infra/stand/.env -f infra/stand/compose.yml logs --tail=80 backend web
```

Секреты из `infra/stand/.env` не включаются в архив и не печатаются инициализатором. База и документы хранятся в собственных Docker volumes. Исходный пакет не содержит `.runtime`, `.stand-access`, `media`, дампов БД, тестовых фикстур, `node_modules` или локальных учётных данных.

## Проверка быстродействия

Проверяется обычная работа с наполненной системой: вход нужной ролью, открытие реестра, поиск/сортировка, карточка, PDF, переписка, расчёт и скачивание отчёта. Отдельный искусственный нагрузочный сценарий не входит в комплект. Запись вымышленных дел выполняется только начальным наполнением; измерения выполняются обычными пользовательскими действиями.

## Сборка пакета из репозитория

```powershell
uv export --directory backend --extra stand --locked --no-dev --format requirements-txt --no-hashes --no-emit-project --output-file ../infra/stand/requirements.txt
npm.cmd --prefix frontend run build
& .\backend\.venv\Scripts\python.exe infra/stand/package.py
```

Команда наполнения `populate_stand` требует явного `AIS_STAND_MODE=1`, пустой рабочей БД и отсутствия настроенного Google-источника. Её не следует запускать против существующей рабочей базы. Скрипт не удаляет записи.
