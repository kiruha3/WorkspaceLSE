# Автономный установочный набор Windows x64

В готовом ZIP проекта установщики находятся в `installation/packages/`:

| Файл | Назначение |
|---|---|
| `Git-2.51.2-64-bit.exe` | Git для получения и обновления кода |
| `python-3.13.12-amd64.exe` | Python для Django |
| `node-v22.20.0-x64.msi` | Node.js с npm для Vue/Vite |
| `uv-x86_64-pc-windows-msvc.zip` | Готовые исполняемые файлы uv |
| `embedded-postgres-binaries-windows-amd64-17.11.0.jar` | Переносимый PostgreSQL; Java не нужна |

Версии соответствуют проверенному окружению. URL и SHA-256 зафиксированы в `packages.json`. Совместимые установленные инструменты используются повторно. uv и PostgreSQL распаковываются локально в `.runtime/`; отдельная служба PostgreSQL не устанавливается.

В папке `installation/offline/` дополнительно находятся все Python wheel-пакеты, requirements из `backend/uv.lock` и отдельный npm-кэш для `frontend/package-lock.json`. Манифест проверяет контрольные суммы файлов и соответствие lock-файлам проекта. Этот комплект рассчитан на Windows x64 и Python 3.13.

## Установка одной командой

Распакуйте весь ZIP в постоянную папку, например `E:\WorkspaceLSE`. Откройте **PowerShell от администратора**, перейдите в распакованный корень проекта и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installation\Install.ps1
```

Права администратора нужны для отсутствующих системных Git/Node/Python. Скрипт:

1. Проверяет наличие и контрольные суммы установщиков и библиотек. При неполном или устаревшем комплекте останавливается, ничего не скачивает.
2. Устанавливает недостающие Git, Node.js и Python 3.13, распаковывает uv и PostgreSQL.
3. Создаёт `backend/.venv`, устанавливает зависимости Python и JavaScript из локального комплекта по зафиксированным версиям и хешам.
4. Создаёт новую локальную PostgreSQL БД, применяет миграции и начальные справочники.
5. Создаёт `setup` и начальные карточки сотрудников, проверяет Django и собирает фронтенд.

**Для установки готового полного ZIP Интернет не нужен.** Python устанавливается через `uv` с `--offline --no-index` из локальных wheel-файлов. npm использует `--offline` и копию комплектного кэша, без аудита и lifecycle-скриптов, которые могли бы самостоятельно запускать загрузки. Фронтенд затем собирается штатной командой проекта.

Скрипт установки не создаёт демо-экспертизы, не импортирует таблицу и не запускает веб-серверы. Он откажется выполнять свежую установку поверх существующего локального кластера БД; для обновления используется [основная инструкция](../docs/RUNNING.md#8-повторный-запуск-обновление-и-остановка). Если установка оборвалась уже после создания БД, продолжите с миграций/начального наполнения из раздела 3 инструкции, без удаления данных.

## После установки

Пароль первого входа смотрите локально:

```powershell
Get-Content .runtime/local-login.json
```

Первое окно PowerShell в корне проекта:

```powershell
& ./backend/.venv/Scripts/python.exe infra/local.py backend manage.py runserver 127.0.0.1:8000 --noreload
```

Второе окно:

```powershell
npm.cmd --prefix frontend run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173), войдите как `setup`, назначьте права, сохраните Google-источник и импортируйте журнал с предпросмотром. Дамп для выбранного пути не нужен. Доступ по адресу машины настраивается командой `infra/local.py web-hosts` из раздела 6 основной инструкции.

Чтение Google-таблицы требует связи с Google. Если рабочая машина полностью без Интернета, заранее выгрузите журнал в XLSX на другом компьютере и загрузите его через интерфейс. Локальная работа с системой и файлами не требует Google.

## Проверить комплект без установки

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installation\Install.ps1 -CheckOnly
```

Эта команда проверяет наличие файлов, SHA-256 и соответствие зависимостей lock-файлам; ничего не скачивает, не устанавливает и не меняет базу.

Только подготовка инструментов, без зависимостей проекта и БД:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installation\Install.ps1 -ToolsOnly
```

## Подготовить автономный комплект на машине с Интернетом

Установщики и кэши библиотек не хранятся в Git. Обычный Git-клон сам по себе не является автономным комплектом. На машине разработки с Git, Python 3.13, Node.js/npm и uv выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installation\Prepare-Offline.ps1
```

Подготовка скачивает пять пакетов инструментов и все зафиксированные библиотеки. Рабочие `frontend/node_modules`, `backend/.venv` и БД не меняются: npm и pip выполняются в отдельной временной папке. Временные папки после подготовки удаляются. Кэши логов и пользовательские настройки не добавляются в набор.

После коммита исходников соберите переносимый архив проекта с установщиками и библиотеками:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installation\Build-Bundle.ps1
```

Архив `WorkspaceLSE-windows-x64-offline-<коммит>.zip` и его SHA-256 появятся в `outputs/`. Сборка сама ничего не скачивает и требует заранее подготовленные зависимости. В архив попадают исходники коммита, пять установщиков и только перечисленные в манифесте библиотеки. Рабочая БД, пароли, `media/`, журналы и локальные настройки в комплект не включаются. ZIP из `git archive` не содержит `.git`.

При изменении `backend/uv.lock` или `frontend/package-lock.json` повторите подготовку. Старый кэш с новыми версиями не принимается. Проверка сравнения lock-файлов учитывает различие LF/CRLF в Windows.

Проверки обработки неполного/повреждённого комплекта, устаревшего lock-файла и LF/CRLF можно выполнить без сторонних тестовых инструментов:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installation\Test-OfflineAssets.ps1
```
